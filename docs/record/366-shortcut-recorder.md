# 366 — `ShortcutRecorder` (`KF-AK`)

Class `M`, no divergence. Alloy lets a user rebind a command and needs the macOS-style field: press it, press a chord, get a `KeyboardShortcut` (the design is PR5 of the shortcut series: `KF-AG` display text, `KF-AL` shift normalisation and `unshiftedKey`, `KF-AI` claims, `TRM-U`..`TRM-Y` key capture, `FW-` focus within). Alloy's binding answers: the recorder draws the current shortcut itself; it records anything, plain letters included, with `Void` closures (Alloy validates); one form everywhere, the unshifted base key plus `.shift`.

- `Sources/MetalUI/ShortcutRecorder.swift`: the component and `ShortcutRecorderOutcome.of(_:)`, the whole key table as a pure function.
- `Sources/MetalUI/KeyPress.swift`, `Window.swift`, `KeyCapture.swift`: `KeyPress` gained an internal `unshiftedKey` filled from `KeyEvent.unshiftedKey` at both construction sites, so the recorder can record `⇧/` as `"/"` + Shift on AppKit (`charactersIgnoringModifiers` is "?") as on SDL.
- **The finding that changed the brief.** Built as briefed (`.focusable(interactions: .edit)`), the recorder was the window's first-draw seat (`FC-E`; SwiftUI seats an `.edit` focusable too, probe `I8`): a window whose first focusable it is opens **already recording** ("Press Shortcut" at open), where ⌘Q would be swallowed and a `runUntilIdle` spun. It is now `.focusable(interactions: .activate)` plus `onClick { focus = true }`: reachable by Tab and `focused`, started by a press, never seated. The second finding: the accessibility declarations must sit **inside** the focusable (written before it), else the published node is not the focused element and VoiceOver and `TestElement.isFocused` never see the focus.
- Look in the `Box` vocabulary (a flexible frame 96 wide at least, 22 tall; `.surfaceSecondary`, a 1-point `.separator` border, `.focusBorder`): the proposal chain's `focusable` wraps a `KeyboardModifier` whose id is not the accessibility node's.
- "Ending without a key" is one `.onChange(of: isRecording)` that calls `onCancel` unless a key set a flag first; the flag is a class in `@State` (a `@State<Bool>` write re-evaluated the recorder a second time at each end: measured, then changed). The window leaving `.key` clears the focus, and the same path cancels.
- Tests: `Tests/MetalUITestingTests/ShortcutRecorderTests.swift` (18, portable: record, plain letter, lower-case, AppKit- and SDL-shaped ⇧/, ⇧Tab, Escape, ⌫/⌦, ⌘⌫ and ⌥Esc, modifier-only/repeat/release, Tab vs ⌃Tab/⌥Tab, a `CommandMenu` ⌘K item and a `Button` ⌘K, focus moved, window resign, an idle recorder, the first draw, accessibility, display text), `ShortcutRecorderCostTests.swift` (4), `Tests/MetalUITests/ShortcutRecorderInternalTests.swift` (2).

- **Follow-up (Alloy): free replay.** MetalUI has no automatic retention of an `Equatable` component, so `ShortcutRecorder` is now a thin public wrapper whose content is the internal `ShortcutRecorderField` `.equatable()` (closures excluded as before). An idle recorder is 3 requests / 2 skips by default, equal to the window without one (was 7 / 1); start and end of a recording are one field evaluation each (the `@FocusState` invalidates the field). Mutation shown red: return `field` without `.equatable()` (idle, keystroke and start/end tests). The idle-recorder literals below are the pre-wrapper ones for the plain case.
- Cost (measured, `canImport(Darwin)` literals; per frame elsewhere): idle recorder +4 requests (7 with the test window's 3), `.equatable()` 3 and one more skip; a `TextField` keystroke 7 plain, 3 equatable and 3 without a recorder; start and end of a recording one evaluation each; a parent change re-enters nothing; a window without a recorder has `keyCaptureCount == 0`.
