# 321 - `onKeyPress` in generic code folds too (`KF-AE`)

Branch `fix/onkeypress-generic-fold` from master `2275d2a0`. Class `A`, no divergence. Follow-up to record 319 (`KF-AD`), reported by Alloy: a helper `extension ElementGroup { func codeKeyHandlers(...) -> some ElementGroup { self.onKeyPress(...).onKeyPress(...).onKeyPress(...) } }` still added one element request per steady frame.

**Root cause.** `KF-AD`'s fold is an overload on the receiver's static type (`_KeyPressFolding`). Inside a generic extension the static type is `ElementGroup`, so overload resolution took `KF-AC`'s `ElementGroup.onKeyPress`, which wraps the receiver in `_wrap(ModifierLayer(...))`: for a receiver that is not a flat chain (an `AccessibilityModifier`, an `OverlayModifier`, a `LifecycleScope`) that wrapper is an `Element` entered as a group member on every frame (`Frame.elementRequests`). SwiftUI's `extension View { func x() -> some View }` costs nothing, so this was a divergence to remove, not one to record.

**Fix: dynamic dispatch (option b).** `ElementGroup` gains `associatedtype KeyPressed` (default `ModifiedElement<LayerBase>`) and `_addingKeyPress(_: KeyPressRegistration) -> KeyPressed` (default: `KF-AC`'s wrapper). The `ElementGroup` spellings return `KeyPressed` and call the requirement, so a generic call reaches the conformer's witness: `ModifiedContent` (through `ModifierLayerKind._addingKeyPress`: legacy outermost layer, or `KF-AD`'s `keyboard` layer), `LifecycleScope` (`LifecycleScope<Content.KeyPressed>`), `AccessibilityModifier` (own `Handlers.keyboard`, registered at its bounds) and `OverlayModifier` (own handler list, registered at its bounds before both sides prepaint). `AccessibilityModifier` and `OverlayModifier` also gain `KeyboardLayerHolder` (a `.focusable()` over them takes the handlers), and `AccessibilityModifier` conforms to `_KeyPressFolding`, so written directly it no longer costs the `KeyboardModifier` request either.

**Alternatives.** (a) A transparent build-time wrapper: needs run-time casts on the content, still shifts identity for a content with no layer, and keeps a type that is not the receiver's. (c) A retained wrapper: an unchanged frame still enters the member, so the request stays. (b) leaves the identity levels of everything under a chain, wrapper or scope unchanged.

**Before / after** (`FrameWork.elementRequests`, a steady frame, with versus without the helper, `Box { ... }` root): Alloy shape 1 (`VStack{}.frame.onChange x3.accessibilityElement(children: .contain).accessibilityIdentifier(...)`): 4 without, 5 before, 4 after. Shape 2, overlay over an `.equatable()` component as the receiver: 5, 6 before, 5 after; under a `.onChange` scope: 5, 6 before, 5 after. Scope over a chain: 3, 4 before, 3 after. Retained hits/misses and ineligible counts equal with and without (0 ineligible in all; the equatable overlay hits once in both).

**What still costs.** A receiver with no layer (`Pair`, `ForEach`, `EquatableComponent`, a user group) keeps `KF-AC`'s one wrapper element; so do the scopes other than `LifecycleScope` (`TransactionScope`, `CoordinateSpaceScope`, `GeometryChangeScope`, `GlassTagScope`).

**API.** `ElementGroup.onKeyPress` returns `KeyPressed` (was `ModifiedElement<LayerBase>`); migration note added. `existingConformersKeepTheirOverload`'s generic helper now asserts `G.KeyPressed`, and a `Pair` still wraps.

**Tests** (`ElementGroupKeyPressCostTests.swift`, 9 to 14): generic helper over the accessibility chain, over an overlay (receiver and under a scope), over a chain and a scope, over a legacy chain; routing (later-written first, ancestor first) over an accessibility wrapper, an overlay and a scope; `.focusable()` over a wrapper and an overlay owning the handlers. **Mutations shown red**: see the commit's report (`AccessibilityModifier`, `OverlayModifier`, `LifecycleScope`, `ModifiedContent` each left on the default wrapper; wrapper's `takeKeyPresses` and the overlay's registration off).

**Docs.** Ruling `KF-AE`, the rule in `docs/rules/input-focus.md`, inventory family `key-press-fold` (extended), migration note.
