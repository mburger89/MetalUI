# 279. MetalCreator's toolbar symbols for Linux and Windows (`SYM-Q`)

Branch `feat/icons-metalcreator-g`. MetalCreator's toolbar uses nine SF names that macOS draws through AppKit but the bundled table lacked, so Linux and Windows drew nothing. This adds them to the bundled Lucide table (class M, no new divergence: 230 covers the Lucide stand-in look).

- **Mapping.** `arrow.uturn.forward` -> `redo-2` (the pair of `undo-2`); `square.and.arrow.up` -> `share`; `plus.magnifyingglass` -> `zoom-in`; `minus.magnifyingglass` -> `zoom-out`; `sidebar.left` -> `panel-left`; `rectangle.lefthalf.inset.filled` -> `panel-left` with a filled left strip; `rectangle.bottomhalf.inset.filled` -> `panel-bottom` with a filled bottom strip; `house` -> `house`; `camera` -> `camera`.
- **Filled halves.** Lucide 1.70.0 (same pinned tarball, sha256 `3d1f09df...120f16a`, re-verified) has no filled panel, and `Entry.filled` fills the whole outline, which SF does not. `Entry` gains `fillShape`, the name of a vendored closed region filled under the stroke; `scripts/vendor-lucide.py` gets a `SHAPES` table with `panel-left-fill` (x 3...9) and `panel-bottom-fill` (y 15...21), hand-written path data on the panel's rounded rect. `LucideData.swift` regenerated: 51 icons, 781 opcodes, 2954 coordinates. `LICENSE` byte-identical; `share`, `zoom-in`, `zoom-out` are on the Feather list, so `THIRD-PARTY-NOTICES.md` names them.
- **Segmented picker with `Image` segments: works, no change.** A segment's content is any element. On macOS (AppKit route, `harnessWindow`) a `Picker(...).pickerStyle(.segmented)` of `Image(systemName:)` segments gave two `radioButton` elements 44 x 24 labelled "home" and "camera" (AppKit's description) with the glyphs drawn. On the bundled route (seam on) the segments are 39 x 24, the glyphs are painted, and the segment labels are "Play" and "Undo" for `play` and `arrow.uturn.backward`; a name outside `SymbolAccessibilityLabels.table` (`house`, `camera`, and the nine new names) records no label there. `Label(_:systemImage:)` does not exist in MetalUI yet (`SYM-M`, carried). Gaps: measured SwiftUI labels for the new names; `Label`.
- **Tests** (`PortableIconTests`): `alloyNames` is 51; the vendored count is 51; new `metalCreatorsToolbarSymbolsResolveAndDrawWithFilledHalves` (mapping, ink, fill-under-stroke layers with bounds, a pixel in the filled half is solid and in the other half empty, `sidebar.left` stays an outline); new `aSegmentedPickerShowsImageSegmentsWithTheirGlyphAndLabel`.
- **Mutations** (`swift test --build-system native --no-parallel --filter PortableIconTests`, restored): **M279a** the `camera` row dropped: the new test (3 issues) and `everyAlloyNameIsABundledIconInsideItsViewBox` redden. **M279b** `fillShape` removed from `rectangle.lefthalf.inset.filled`: the layer-count expectation reddens.
