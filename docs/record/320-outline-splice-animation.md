# 320 - The expand/collapse splice animation of a content list (`OG-`, lane 7)

Branch `feat/outline-splice-animation` from master `216447e4`. Lane 7, the last, of the hierarchical lists (design `docs/superpowers/specs/2026-11-15-outline-disclosure-design.md` section 5; decisions `docs/superpowers/2026-11-15-outline-disclosure-decisions.md`, `OG-H` finalised, `OG-P` added). Class A for the behaviour (no public API), **divergence 1088 added** (live count 225, next label 242). Record 319 is `onKeyPress`'s.

**What.** Inside a content `List` (the content form and `OutlineGroup`/`List(_:children:)`), an expansion or collapse by a chevron click, the arrow keys, an accessibility expand/collapse or a ⌥ cascade, or a write inside `withAnimation`, slides the rows after it over 245 ms, fades the inserted rows in and ghosts the removed rows out from the previous scene. A bare binding write snaps. The given animation's duration is ignored, as SwiftUI's is (probe `P-N3`). Reduce Motion: a cross-fade only. The eager `DisclosureGroup` and `LazyVStack` are unchanged.

**How** (`Sources/MetalUI/OutlineSplice.swift`, hooks in `LazyStack.swift`, `DisclosureGroup.swift`, `LazyTree.swift`, `OutlineIndex.swift`, `ListContent.swift`, `Frame.swift`, `Window.swift`, `AnimationStore.swift`). Layout is untouched: rows sit at their final places. `AnimationStore.splices` keeps each list's last painted rows (id, unit, y as drawn, scene range); the next frame's diff by id classifies kept (slide), inserted (fade) and removed (ghost) rows when input marked the toggle (`OutlineSplice.noteInput`) or the frame carries a transaction. Paint displaces kept rows with `paintWithDeviceMap`, fades inserted rows under a `.fade` scope, and draws ghosts from `previousScene` slices. Clock: `noteActiveAnimation()`. See `OG-P` for the rules.

**The curve fit.** 70 recorded samples (five runs, 14 each, 7 ms apart from about 15 ms) over a 64 pt travel are front-loaded, not ease-in-out: 65 % of the travel in 37 % of the time. Linear is 10.3 pt RMS off, the standard `easeInOut` 15.8 pt; the least-squares Bezier is (0.29, 0.15, 0.20, 0.91), start 10.6 ms before the first sample, 0.60 pt; CSS `ease` (0.25, 0.1, 0.25, 1) is 0.78 pt at that start and 1.7 pt at 15 ms, and is the curve used. The curve's second half was not printed in the probe, so the fit is pinned there only by the end point.

**Tests** (`Tests/MetalUITestingTests/OutlineSpliceTests.swift`, 13, window level, `advance(by:)` as the clock; oracle values written down from an independent Python bisection of the same curve): the slide at 49, 98, 122.5, 196 and 245 ms in both forms; the exact final layout (scene equal to the snapped one, no frame afterwards); the insertion fade; the removal ghosts at their old places and fading; bare write snaps, `withAnimation(.linear(duration: 2))` takes the measured 245 ms; Reduce Motion; `needsRedraw` false mid-animation (the `noteActiveAnimation` clock); keys, accessibility and ⌥ cascade; a toggle outside the realised window, below and above, slides nothing; a standalone group snaps; lane 8's counters during (0 evaluations, 0 rebuilds, 1 hit a frame) and after (0, 0, 1 hit, 3 checks) the splice.

**Mutations shown to redden them** (each its own run): offset not applied (6 tests); linear curve (7); duration 0.6 (9); `p` for `1 - p` (6); no fade scope (2); ghosts not drawn (1); ghost alpha `p` (1); every write animating (1); Reduce Motion ignored (1); `requestAnotherFrame` for `noteActiveAnimation` (3); the toggle mark dropped (8), the data form's `set` mark dropped (2), the cascade request's mark dropped (1); the animation switching the flatten cache off (1); ghosts never expiring (2). **Inert mutation, recorded so nobody expects it:** dropping the `lastUnmoved >= 0` guard in `classify` changes nothing, because the next check (the first shifted row must follow the last unmoved one) already refuses a splice with no unmoved row.

**Costs and gaps.** One scene retained a frame per window with a content list; per-row range bookkeeping is a dictionary of the realised window. Hit testing and accessibility follow the final layout during the slide (1088). A ghost needs the row's paint to have run in the previous frame (a retained replay leaves none). The glyph swap is instant. The 15 ms AppKit lag before motion is not reproduced.
