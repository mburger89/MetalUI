# Record 232: bundled icons (Alloy gap G3, PR 2)

Branch `feat/lucide-icons` (based on `feat/symbol-images`, PR #227, record 230). Class `M` for the new API (`Icon`), `A` for what `Image(systemName:)` now draws off Apple platforms. Rulings `SYM-I`, `SYM-J`, `SYM-N`, `SYM-O` (`docs/superpowers/2026-11-07-symbol-images-decisions.md`, next `SYM-P`). Divergences 230 and 231 added (211 live becomes 213, next label 232). **Linux and Windows now draw `Image(systemName:)`**: record 230 left every name there an empty 0 x 0 leaf.

## 1. What was built

- **`MetalUIIconData`** (new portable target, **imports nothing**; in the manifest's portable list, `MetalUI` depends on it, `LICENSE` and `VENDORED.md` excluded as `CStbImage`'s are). `package` data only: `IconPathData { ops: [UInt8], coords: [Float] }`, opcodes 0 move, 1 line, 2 cubic, 3 close, on Lucide's 24 x 24 grid, and `LucideIcons.data(named:)`. No parser. 29 icons, 421 opcodes, 1504 coordinates, `LucideData.swift` 15 KB, `LICENSE` 3.2 KB.
- **`scripts/vendor-lucide.py`** (run with `python3 -I`; reads the tarball with `tarfile`, nothing extracted or executed; refuses unless the sha256 matches the argument and `package/LICENSE` starts "ISC License" and carries the Feather MIT portion). Converts `path` (M L H V C S Q T A Z, absolute and relative, compact arc flags), `circle`, `ellipse`, `rect` (with `rx`), `line`, `polyline` and `polygon` to the four opcodes; SVG arcs become cubics of at most 90 degrees. **Test 3 caught a bug in its first output**: a relative `m` at the start of a second `<path>` element continued from the previous element's end point (`x`, `pencil`, `circle-x` and `square-arrow-out-up-right` ran off the grid); each element now starts at the origin, as SVG says.
- **The name table** `BundledSymbols.table` (`Sources/MetalUI/BundledSymbols.swift`): 38 SF names onto the 29 icons (`SYM-I`). `robot` does not exist on macOS or in the Lucide set; `cpu` is the agent icon, `brain.head.profile` maps to `brain`. `.fill` exists only for the closed outlines play, stop, star, circle, square and triangle (a fill layer beneath the stroke); every other `.fill` falls back to the base name through `resolveSymbolName`.
- **API (MetalUI-only, class M):** `Icon: Hashable, Sendable` with `init(viewBox: Size<Pixels>, layers: [Icon.Layer])`; `Icon.Layer(_ path: Path, paint: Paint, level: Level = .primary)`, `Layer.Paint` = `.stroke(width: Pixels, cap: LineCap, join: LineJoin)` | `.fill(FillStyle)`, `Layer.Level` = `.primary` | `.secondary`; `Icon.bundled(_ systemName: String) -> Icon?` (main actor; the exact SF name); `Image(icon: Icon, label: Text)` and `Image(decorative icon: Icon)`. `Image.Content` gained `.icon(Icon)`: `swift package clean`.
- **Route (`SYM-N`).** `SymbolRoute.usesBundled` is true wherever AppKit is not importable; on macOS only while the `package` static `SymbolRoute.forcesBundled` is set (default off). A bundled symbol and an `Icon` share one layout, one paint and one accessibility rule.
- **Layout, stroke and paint (`SYM-J`).** A square box of `pointSize x f[scale]` with `f` = 0.94 / 1.15 / 1.46 (small / medium / large) and first and last baseline `side - pointSize x d[scale]`, `d` = 0.09 / 0.19 / 0.35. Stroke `layerWidth x (side / viewBox) x w(weight) / 2` with `w` = 1, 1.25, 1.5, 2, 2.25, 2.5, 2.75, 3, 3.25 from ultra-light to black (nearest `Font.Weight`), so Lucide's own width 2 is the table. Painted by `pass.drawPath` (the existing `RasterCache`, crisp under transforms, retained replay, both renderers; no shader change): one uniform transform, the larger view-box side filling the smaller side of the bounds, centred; the foreground style (never the tint); a `.secondary` layer under `.hierarchical` at alpha x 0.5; `.monochrome` and `.multicolor` draw every layer in full. A resizable symbol answers the proposal.
- **Accessibility (`SYM-H`).** A bundled symbol is an `.image` labelled with SwiftUI's table entry for the resolved name; a name outside the table (`circle`, `triangle`, `square`) records no label rather than an invented one; `Image(icon:label:)` is labelled by its text; `Image(decorative:)` and `.accessibilityHidden(true)` record nothing. No hitbox.
- **Carried (`SYM-O`).** An `Icon` or bundled symbol is not a cursor image (`PointerStyle.image` returns the arrow) or a native toolbar image (the label alone): paths have no raster to hand them.

## 2. The fit (how the portable box and baseline follow probes S1 and S2)

Sample: 38 SF names (the 30 Alloy names plus star, star.fill, circle, circle.fill, square, square.fill, triangle, triangle.fill) x point sizes 9, 11, 13, 17, 26, 48 x the three scales, regular weight, macOS 27.2 (`NSImage(systemSymbolName:)` with a symbol configuration, the quantities S1 and S2 showed SwiftUI lays out by: H1' width = `alignmentRect.width`, height = `size.height`; H2 baseline = `height - alignmentRect.minY`). The scratch scripts are not in the repo; the readings:

| scale | median of alignment width and image height over point size | median `alignmentRect.minY` over point size |
|---|---|---|
| small | 0.941 (height 0.923, width 0.962) | 0.091 |
| medium | 1.154 (1.154, 1.167) | 0.192 |
| large | 1.462 (1.455, 1.500) | 0.346 |

Shipped (rounded): `f` 0.94, 1.15, 1.46; `d` 0.09, 0.19, 0.35. Errors over the sample: side against SF's width and height, mean 1.85 / 2.17 / 2.81 pt (small / medium / large), maximum 20-31 pt (48 pt rows and wide glyphs such as `brain`, `cpu`, `doc.on.doc`); the baseline's distance above the box bottom against SF's `minY`, mean **0.82 / 1.01 / 1.28 pt** for the fit against 0.99 / 1.13 / 1.39 for the plan's cap-centre model (H3), maximum 8.3 / 10.9 / 13.2 against 9.7 / 10.7 / 14.1. So H2's rule with a fitted descent is a little better than H3 in the mean and is the same kind of rule S2 found; neither is exact because the portable box is square where SF's is not (divergence 230). Spot rows (13 pt medium): `magnifyingglass` SF 15 x 15, baseline 12; portable 14.95 x 14.95, baseline 12.48. `play` SF 12 x 13; portable 14.95 square (the largest visible difference for the Alloy set).
