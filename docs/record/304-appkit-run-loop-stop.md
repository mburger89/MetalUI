# 304 - AppKit tests ended the run with exit 0 and no summary (the event-signal block)

Class M (tests only), no divergence, no public API. `swift test --build-system native --no-parallel --filter AppKit` died after about 100 tests with no `Test run with` line and exit 0, in a different AppKit test depending on timing (here `theMenuBarIsRefreshedWhenAMenuOpens`, `theEditMenuReachesTheFocusedFieldAsItsKeys`, `appKitTitleBarMetricsSurviveResizeAndTitleChange`); the unfiltered run ended after about 2600 tests. It is record 61 section 9's hazard again, not a regression of `AS-T`, `TW-A` or `RW-X`: checked out at `990e074b`, the parent of #302, the filtered run dies the same way, and an unfiltered run had passed only because the suite's timing happened not to put a stop on the outer loop.

**Cause.** Swift Testing's outermost loop is `CFRunLoopRun` inside `swift_task_asyncMainDrainQueue`; its return is `exit(0)`. An interposing dylib (`DYLD_INSERT_LIBRARIES` into a directly launched `swiftpm-testing-helper` with the env `swift test` sets) printing a backtrace at every `CFRunLoopStop(main)` and naming the block that ran it showed each stop was `SignalMainThread()_block_invoke`, queued from `_NSEventThread` via `PushToCGEventQueue`: HIToolbox falls back to stopping the main run loop when no `CGEventQueue` enqueue-signal block is installed. Nested runs (`performClick`, `RunLoop.run`) absorb it; one reaching the outer loop ends the process. The earlier workaround (`appKitEventSignal`: run `-[NSApplication run]` once and stop it) installs that block through `_SetCGEventQueueEnqueueSignalBlock` on older systems; on this one (macOS 27, interposed) the setter is **never called**, so the workaround was inert and the stops kept coming (13 in a filtered run, all `SignalMainThread`).

**Fix.** `installAppKitEventSignal()` (`Tests/MetalUITestSupport/AppKitEventSignal.swift`, test-only) calls the setter through `dlsym` with a block that only wakes the main loop. Every test helper that builds an `AppKitPlatform` or `AppKitWindow` calls it first (21 files; `MetalUIPlatformTests` gained the `MetalUITestSupport` dependency). Result: zero `SignalMainThread` stops in the filtered run, 138 of 138 AppKit tests with a summary. `windowServerTrafficNeverStopsTheMainRunLoop` pins that the setter exists and is called (alone, a nested pump rarely sees a stop: the traffic needs the long preceding sequence, so the setter is the pin; the pump stays as a smoke check). Mutation: return before the setter call, the pin fails.

The private symbol is reached through `dlsym` in the test support target only; shipped code must not. Not done: a production-side install (an async-main AppKit host has the same exposure); SDL's `installAppKitEventSignal` (record 61) may be inert on this macOS too and was not re-measured here.
