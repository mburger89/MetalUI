# 265. CodeView batches row lookups and caches per-frame row styling (Alloy gap G33 d, `CV-AH`)

Branch `perf/code-row-lookups` (master `74628b2e`). Decision `CV-AH` in `docs/superpowers/2026-11-07-code-view-decisions.md`. Class `M`; no divergence added or retired (220 live, next label 241). No public API added.

- **Profile.** An Alloy Instruments run over 200 keystrokes: `Rope.lineStart(row:)` (root walk plus a `\n` scan per call, called twice by `lineRange`), `rowsNeedingHighlights` (a `lineRange` and a `runs(in:)` per visible row, every frame) and `stylingOfLine` (scratch arrays, every layer, a sort, a digest, per painted line per frame).
- **Change.** `CodeSnapshot.lineRanges(rows:)` (package): one `lineStart` seek, then `forEachSlice` forward, each row's start the previous end plus the newline (CRLF handled across slice boundaries). `lineRange(row)` is its one-row case, `offset(of:)` scans to the row's `\n`. `makePlan` fetches the window's buffer rows once (`rangeOf`), `rowsNeedingHighlights` (now `package`) uses the batch. `CodeDecorations` caches `stylingOfLine` per byte range (512 entries, cleared when full) and the last `rowsNeedingHighlights` answer, keyed by `appliedVersion` (the buffer version `sync()` last drained to) and `revision`; either moving clears both.
- **Measured** (`RopeStats.nodesVisited`, 60 rows in a 100 000-line buffer): per-row seeks 720 nodes, `lineRanges` 14 (one row alone: 13). An idle repaint: `stylingComputations` and `needingHighlightScans` stay constant across 5 repaints (they rose every frame before).
- **Tests.** `Tests/MetalUICodeBufferTests/LineRangesTests.swift`: `lineRangesEqualTheOracleAndPerRowLineRange` (edge texts, random texts with CRLF and bare CR, empty, no final newline, clamping), `aWindowOfRowsCostsOneSeekAndAScan`. `Tests/MetalUITestingTests/CodeViewTests.swift`: `anIdleRepaintRecomputesNeitherStylingNorRowScans`, `anEditAndNewHighlightsInvalidateTheRowCaches`. Mutations: `lineRanges` as per-row seeks fails the node-count pin (720 against 14); removing the two cache lookups fails the idle-repaint pin and the cached-ask pin; a cache never cleared fails the invalidation test. The equality test guards correctness (passes under the per-row mutant by design).
- **Not done.** `stylingOfLine`'s own computation is unchanged (it runs once per row per change now); the editing session's `lineRange` calls (`CodeEditSession`) are single-row and stay as they are.
