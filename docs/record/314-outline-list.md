**How.** `ListRowChromeLayout` is a native `ProposalLayout` over the unit's own nodes: content `leading` points in (`12 + 12 depth` for a disclosure label row, whose 13 wide chevron cell it holds; `25 + 12 depth` for any other row of a list whose content TYPE holds a disclosure, the leaf reserving the slot; 16 in a flat list), at least 32 tall with the content centred, the first row's 10 point top inset inside its extent so the lazy index measures it. A unit's depth is `LazyUnitBox.depth` (`LazyNestedSource.depthStep` is 1 for a group's content level, an outline row adds its entry's depth); `isDisclosureHeader` and `selectionTag` ride the box (`LazyUnitSource.lazySelectionTag` reads a tag for an unrealised unit by building the element). The row registers its hit target and accessibility row BEFORE its content's prepaint (`registerAndScope`, so the chevron's tap ranks above it) over the full width, and paints the highlight, inset 10 and radius 8, beneath the content. A content row's value is its `.tag` when that casts, else its unit's scroll id (the `ForEach` element id, an outline row's element id). The list is the single focusable; its lead and anchor live at `list/$listlead` (the lazy stack's origin is at the list's id and the state table keys by id alone); a unit box's own key is not unique (an outline row's is its static source's) so a row's id is named by the table's key. `DisclosureGroupBody.listHeader` is the list's label row (`ListRowChrome.isActive` is set for the engine's layout so `lazyTreeFlattenBody` and `OutlineGroupSource` pick it): the chevron is `.secondary` (0.498 black over white = #808080, the probe's light chevron; dark draws a little brighter than the probe's #7C7C7C), a glyph swap, hidden from accessibility, an `onTapGesture`.

**Deviations from the brief.** (a) The reveal needed no new mechanism: a content list flattens before it resolves requests, so `scrollTo` of an id the same transaction made visible resolves against the post-expansion units (`OG-L`); the labelled divergence records the stronger guarantee and the mutation shows the test depends on it. The row is in view one frame after the writes' frame (the frame the resolution asks for), as any `scrollTo`. (b) A row's accessibility element is a sibling of its content's text, not its parent (the content's ids hang under the list; nesting needs per-unit parents): carried to lane 5 with ← → and ⌥. (c) The selection colour is the data list's (tint, else accent): SwiftUI's was not measured (human check OG1). (d) `ListContentBody` has to be an `Element` (the `Row: Element` bound), so it publicly carries the three `Element` methods as no-ops.
