**What.** `OutlineGroup<Data, ID, Parent, Leaf, Subgroup>` with SwiftUI's five generics, the constrained extensions and four inits (root element or collection, `Identifiable` or `id:`), `children: KeyPath<DataElement, Data?>`; `nil` is a leaf, non-nil (even `[]`) a group. `OutlineSubgroupChildren`, a public empty `Component` (class M). In a `VStack` it is the nested `DisclosureGroup`s it stands for; in a `LazyVStack` in a scroller it is read from its data through an `OutlineIndex`: only the window is built, a collapsed group's contents are never read.

**How.** `Sources/MetalUI/OutlineGroup.swift`: `OutlineGroupBody` (a `Component`, one `ForEach` of the roots) and `OutlineNode` (a `Component`: `if children != nil { DisclosureGroup { ForEach(children) { OutlineNode } } label: {...} } else { leaf }`), the eager form; the group's `@State` holds the index. `Sources/MetalUI/OutlineIndex.swift`: `OutlineIndex` (entries, expanded groups, validation, one iterative rebuild), `OutlineScopes` (the ids of each level, equal to the eager structure's and to the hand-written recursive form's), `OutlineGroupSource` (realises a row from the index under those ids: a group as its disclosure's label row, a leaf as its content). The lane-2 gate reads it: `OutlineGroup: LazyTreeType, LazyTreeFlattenable`. **Expansion** is each group's own `DisclosureGroupBody.local` slot, read by `peek` (`DisclosureSlot`) without building the group; a toggle bumps `expansionGeneration` through `DisclosureGroupBody.onToggle`. **Retention (`P-E5`)**: the outline's disclosure keeps its descendants' state while collapsed (`OptionalGroup.retainsStateWhenAbsent`, the eager form), and the index marks every expanded group and a `hidden` set of expanded groups below collapsed ancestors live each frame, because the table reaps an unmarked slot past 256 entries. **Removal**: the eager `ForEach` resets a dropped element (`noteLoop`); the lazy rebuild calls the new `StateTable.noteRemovedSubtree` for a group the data dropped while its parent is expanded.

**Counters** (internal `LazyWork`, public `FrameWork.outlineChildrenReads`, `outlineIndexRebuilds`, `outlineIndexValidations`, mirrored in `BuildWork`): validations are `1 + expanded groups + rows of the last window`; reads count every `children` read (equal to the data's own log, to the unit).

**Choices and deviations.** (1) The look outside a `List`: a group row is lane 1's row, children not indented, **a leaf is its content as written with no chevron slot** (`P-L2` is inside a `List`; unprobed here; lane 4 sets the slot). (2) A visible row's own `children` is read once per rebuild to tell group from leaf, so only a collapsed group's CONTENTS are never read. (3) An `OutlineIndex` change the checks cannot see (a row entering the window whose data changed) is caught when the row is realised and rebuilt the next frame. (4) A row is one unit in a lazy stack (content with several members is one unit with several nodes). (5) No subtree counts: the flat array is depth-first, nothing here needs a subtree's size. (6) The `Binding` forms are not offered.

**Tests** (`Tests/MetalUITestingTests/OutlineGroupTests.swift`, 15). Collapsed contents never read and the counter equals the log; scroll frames rebuild 0 and validate `1 + 1 + window`; the click's own frame rebuilds once and idle frames 0; a rename in the window rebuilds once and the neighbour row has not moved; a count change (insert above, remove below) rebuilds once and keeps the rows; `P-E5` retention in both forms; a removed group returns collapsed in both forms; the four inits and an empty array as a group; a 10 000-child folder (1 rebuild, 12 realised, 10 001 reads); a `VStack` outline; equal work at 500 and 5 000 siblings; identity equal to the hand-written recursive form and between `LazyVStack` and `VStack` (accessibility ids); a leaf keeps its `@State` through a scroll; a hidden group's expansion survives the table's reaping.

**Mutations shown to redden them.** The rebuild treating every group as expanded (collapsed-content, retention, removal, key-path forms, expansion tests); no window validation (rename, scroll); validation always failing (scroll, 10k, count, rename); the toggle not bumping the generation (the click-frame test only: the realised row's own check masks it one frame later); no `noteRemovedSubtree` (removal test); no marking of hidden groups (the reaping test); no count check (the count test); the children slot numbered 0 or the leaf branch numbered 0 in `OutlineScopes` (identity, retention, removal, state tests); `keepsHiddenState` false (the eager retention).
