# 322 - Image and `Label` menu items (`MN-AP`)

Branch `feat/menu-item-labels` from master `2e021ce6`, merged with master `ccd6cc3a` (record 321). Class `A`, divergence 242. Alloy's request: a session menu with `Button { … } label: { Label(session.name, systemImage: "circle.fill") }` and a tinted status dot per session.

**Probe** (`docs/probes/swiftui-menu-label-items.swift`, macOS 27.0, run twice, byte-identical): SwiftUI's `NSMenu` gives each of `Button(_:systemImage:)`, a `Label` in a `Button`, a bare `Image` beside a `Text`, `Toggle(_:systemImage:)` and `Menu(_:systemImage:)` (and its items) an `NSMenuItem.image`; untinted it is a **template** (15x15 at 14 pt). **`.foregroundStyle(.green)` on the `Label`, the `Button`, the `Image` or the `systemImage:` button has no effect** (template, black). **`.tint(.green)` on the `Button` gives a non-template image in system green**, and `.symbolRenderingMode(.palette)` + `.foregroundStyle` on the `Image` does too. A bitmap is a non-template image at its own size; an unknown symbol or asset name draws no image; `.labelStyle(.titleOnly)` drops it. So for the status dot Alloy writes `.tint(.green)` on the `Button` (or a group above it), not `.foregroundStyle`.

**Landed.** `Label<Title, Icon>` (a `Component`: icon, 8 points, title) with `Label(_:systemImage:)`; `Button`/`Toggle`/`Menu` `systemImage:` initialisers; the closed `MenuItemLabel` (SPI requirement) that `Text`, `Label<Text, Image>` and an `EnvironmentScope` over either conform to, replacing `where Label == Text` on the menu conformances; `_MenuContext.tint`; `MenuNode.image` -> `PlatformMenuItem.image` (`PlatformMenuImage`: symbol, `Rgba?` tint); `AppKitMenuBuilder.image(for:)`; `MenuPanel`'s image column and `paintMenuImage` (bundled Lucide icon through `drawPath`, in the tint or the text colour; `Frame.menuIconsPainted`, frame-local). `MenuContent` stays closed; `aPickerIsNotAMenuItem` still holds for `Picker`/`Section`.

**Not offered:** `labelStyle` (divergence 242), bitmap `Image` items (MetalUI has no `Image(nsImage:)`), the palette route to a tint, attributed (`foregroundStyle`d) menu titles.

**Tests** (`MenuLabelItemTests`, `AppKitMenuTests`, `MenuCompileGuards`), each shown red under a mutation: dropping `image:` in `Button._menuNodes`; not forwarding `context.tint` through `EnvironmentScope`; the untinted `NSImage` not a template; the palette configuration skipped; `paintMenuImage` skipped; the tint ignored at paint; the image column reserved for an unknown name.

**Not run:** the drawn menu on Linux/Windows (the paint is the portable `Frame` path, covered by the macOS suite's in-window menu); a human look at the NSMenu dot colour against SwiftUI's (the probe reads the baked colour, system green, where MetalUI's `Color.green` light value resolves to #34C759).
