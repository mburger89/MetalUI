# 335 - Terminal emulator core: storage and parser (`TRM-F`..`TRM-J`)

Branch `feat/terminal-emulator-core` from master `ff73af7c`; Phase 1 PRs 1.1 and 1.2 of `docs/superpowers/plans/2026-11-16-terminal.md` as one branch. Class M, no divergence label. Ids `TRM-F`..`TRM-J` only; the other `TRM-` ids belong to parallel branches, so the decisions doc's "next unused" line will conflict when they merge.

**What landed.** A new UI-free target and library product `MetalUITerminal` (Foundation-free in practice: nothing imports even Foundation yet) in the root package's portable target list (`PC-A`), plus `MetalUITerminalTests`. Public: `TerminalSize`, `TerminalPosition`, `TerminalRange`, `TerminalSelection`, `TerminalEmulator` (`init`, `firstRow`, `feed`, `modes`, `publishSnapshot`, `rowText`), `TerminalSnapshot`, `TerminalDamagedRow`, `TerminalCursor`, `TerminalModes` with `MouseTracking`, `MouseEncoding` and `TerminalCursorStyle`, `TerminalRow`, `TerminalCell`, `TerminalAttributes`, `TerminalColor`; every signature is the frozen one. Not declared yet, because not implemented: `resize`, `drainEvents`, `TerminalEvent`, `selection`, `selectedText`, `search`, `scrollViewport`, the encoders, `TerminalSnapshotSource`.

**Storage (`TRM-F`).** `TerminalRow` is a struct of two arrays and four scalars: the UTF-8 text of its cells and run-length attribute spans (empty for default text), plus width, used columns, an ASCII flag and a soft-wrap flag. Column and byte offset coincide for ASCII rows, so the hot path appends a slice; a wide or combining write scans cells. `cell(at:)` and `graphemes` build `TerminalCell` values on demand. A row entering scrollback is compacted in place and appended to a lazily growing ring. Census of 10 000 x 120 ASCII rows (counted: array capacities, 32-byte headers, 16-byte granules): **1 927 680 bytes, 192 per row**, against a 4 000 000 budget.

**Parser (`TRM-G`).** `UTF8Decoder` (maximal-subpart U+FFFD, the breaking byte re-decoded; the standard library is the test oracle) feeds `VTParser`, a Williams-style ECMA-48/DEC state machine written from the state descriptions, with `:` sub-parameters, C1 as U+0080-U+009F, payload caps in bytes and CAN/SUB aborts. A fast path hands whole runs of printable ASCII to the handler.

**Emulator seam (`TRM-H`).** Printing with autowrap and pending wrap, wide and combining characters, BS HT CR LF IND NEL, CUU CUD CUF CUB CNL CPL CHA VPA CUP, the mode flags; everything else is parsed and dropped until 1.3-1.4. `publishSnapshot` tracks per-row damage, a full first frame and a version.

**Tests (`TRM-I`, `TRM-J`).** 54 tests: parser state table (22 CSI rows, escapes, strings, caps, C1, aborts), UTF-8 table plus 3 000 seeded random streams against the standard library, chunk invariance (every two-way cut and byte at a time over 8 corpus streams, seeded partitions, a random stream; over the parser event log and whole emulator state), seeded fuzz (400 grids, cursor and size invariants), row, ring and census tests, snapshot damage and sharing by identity, ten `.vtfix` fixtures each run whole, byte at a time and cut everywhere, and the gated bench.

**Mutations, each red** (edited, suite run, file restored from a committed copy): the decoder eating the breaking byte; CAN/SUB not aborting; payload cap off by one; the decoder reset between feeds (chunk invariance, fixtures); no pending wrap; no compaction plus spare capacity (the census and two row tests); a wide character not wrapping whole; the cursor clamp one column wide (fuzz, fixtures, movement); OSC dispatching an overflowed payload; attribute spans not merged.

**Bench.** `METALUI_RUN_TERMINAL_BENCH=1 swift test -c release --filter TerminalBench`: plain ASCII, 80-column lines with CRLF scrolling 24 rows into scrollback, 64 KiB chunks, best of four, Apple silicon: The proposal is 300 MB/s.

Measured on the gated test itself (run from a scratch package holding only the target and `BenchTests.swift`, because a full-package release test build did not finish in reasonable time): **521 MB/s** (the same loop as an executable: 496-510 MB/s over three runs). On a machine loaded with other builds the same binary read 140 and 201 MB/s, so the figure is the unloaded best of four; the guard asserts only a 20 MB/s floor. The first version, which copied every scrolled row, ran at 297 MB/s; compacting in place took it to the figure above.

**Not done, on purpose.** SGR, erase, insert/delete, scroll regions, tab stops, alternate screen, replies (1.3); OSC, events, `TerminalSnapshotSource` (1.4); resize and reflow (1.5); selection, search, viewport (1.6); encoders (1.7). The memberwise initialisers of the snapshot value types are internal (`TRM-F` 5); Alloy's fakes need public ones, to be ruled when they ask. `Tests/PortableTests` (the Linux aarch64 determinism package) does not yet include this target.
