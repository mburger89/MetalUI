# 312 - Lazy flatten through `DisclosureGroup`, `Component` and `if`/`else` (`OG-`, lane 2)

Branch `feat/outline-lazy-flatten` from master `2835f3ca`. Lane 2 of the hierarchical lists (design `docs/superpowers/specs/2026-11-15-outline-disclosure-design.md` sections 2, 6, 8; decisions `docs/superpowers/2026-11-15-outline-disclosure-decisions.md`). Class A, **no public API, no new divergence label** (1085-1094 stay reserved). Finalises `OG-C` and the lazy-stack part of `OG-B`.

**What.** Alloy's pattern stays lazy: a `LazyVStack` of `ForEach(children) { NodeRow }` where `NodeRow` is a `Component` whose body is `if folder { DisclosureGroup(isExpanded:) { ForEach(kids) { NodeRow } } label: {...} } else { leaf }`. The units are each row's label unit plus, while expanded, its content's units, recursively; a collapsed subtree is never evaluated; only the window is realised and laid out.

**How** (`Sources/MetalUI/LazyTree.swift`, new; `LazyUnits.swift` gained `LazyUnitTable.realize(globalIndex:)`; `LazyStack.swift` reads its content through `lazyFlattenRoot`). A **type gate** (`lazyTreeCapableType`, cached): a `DisclosureGroup`, or a `Pair`/`if`/`if`-`else`/`ForEach`/adopted member/`Component` holding one. A container whose content type is not capable takes the old `lazyFlatten` unchanged (a plain `if` is still eager, a plain `Component` row one unit: every existing lazy test, the 100k gates included, is untouched). For a capable one the flattening walks the **same ids the eager path numbers** and builds nested levels (`LazyNestedSource`: a scope plus a `LazyUnitTable`), each realised under its own id with its own cursor: `Component` via `enterComponent`; `ForEach` as `LazyTreeForEachSource` (prefix sums over elements, element scopes as `LazyForEachSource`'s, `noteWindowedParent`, never `noteLoop`); `if` at its one slot; `if`/`else` at both slots (taken produced, other absent, an empty source holds the other index); `DisclosureGroup` through `DisclosureGroupBody.lazyTreeFlattenBody`: the body component, its (bypassed) `VStack` as level 0, the label row member 0, the `if` slot member 1 (`makeContent()` only while expanded). Locating a unit is `O(log elements)` per level, so `O(depth * log siblings)`.

**Costs and gaps.** Every element of every expanded folder has its body evaluated each frame (design section 0), nothing below a collapsed folder. The lazy path records no insertion fade (lane 7) and places a group's children by the container's alignment and spacing, not the group's own centre-aligned 0-spacing stack (equal for full-width children and spacing 0). SwiftUI's behaviour here was not probed, so no divergence is spent.

**Tests** (`Tests/MetalUITestingTests/OutlineLazyFlattenTests.swift`, 6, window level; `Tests/MetalUITests/OutlineLazyFlattenIdentityTests.swift`, 2, frame level). Units are label plus expanded content recursively and `lazyUnbounded` 0 (A, A1, A2, A2a, A2b, B, C = 7); a header click inside the lazy stack toggles (7 -> 5 -> 3 -> 4 units); a folder of 10 000 expanded leaves realises **12** units (unit 9 holds the 200 edge, + 1 + 2); a collapsed deep subtree makes 0 body and content calls (control: the open root does); a leaf scrolled out and back keeps its serial; a bare `if` in a `Component` flattens (R, F, G = 3 units); the same tree under `LazyVStack`, `VStack`, `LazyVStack` over one `StateTable` reads the same serials, the lazy element ids are the eager ids less the three groups' own stacks, and every shared id has equal bounds.

**Mutations shown to redden them.** `lazyFlattenRoot` always plain (container eager: units, click and 10k tests, identity); the disclosure's content slot numbered 0 (9 issues over 7 tests); the component's level dropped from the scope (identity and geometry); `makeContent()` while collapsed (the collapsed-subtree test); header omitted (counts, click, geometry); `noteAbsent` before `noteProduced` on the `if`/`else` branch or the disclosure's slot (the scroll-retention and identity tests); `OptionalGroup` not capable (the bare-`if` test). **Inert mutations, recorded so nobody expects them:** `noteLoop` on the tree source's slot and dropping `noteWindowedParent` change nothing, because every element is evaluated every frame and its scope is never noted under a windowed parent. A `noteProduced`/`noteAbsent` swap on the taken branch is inert too (a slot never produced is never reset): only `noteAbsent` before `noteProduced` resets.

**Not done.** `LazyHStack`/grids are unchanged (a grid still calls `lazyFlatten`); the horizontal stack shares the engine and so flattens a capable tree too, untested. `OutlineGroup`, the content `List`, keys, accessibility nesting and the splice animation are lanes 3 to 8.
