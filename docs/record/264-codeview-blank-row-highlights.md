# 264. CodeView stops re-requesting highlights for a blank last row (Alloy gap G32, `CV-AG`)

Branch `fix/codeview-blank-row-highlights` (master `5e2ce935`). Decision `CV-AG` in `docs/superpowers/2026-11-07-code-view-decisions.md`. Class `M`; no divergence added or retired (220 live, next label 241).

- **Root cause.** `CodeDecorations.rowsNeedingHighlights` probes a blank row through its newline byte, which `CodeSnapshot.lineRange` excludes. A provider answering `lineRange(first).lowerBound ..< lineRange(last - 1).upperBound` therefore never reached that byte when the last requested row was blank, and the row stayed missing. `setHighlights` also bumped `revision` unconditionally, so `shouldRequest`'s dedupe (same rows, version, revision) never held and `CodeViewPlan` asked again after every frame (about 35% idle CPU in Alloy).
- **Change.** (c) `setHighlights` extends the stored extent through the newline when the request in flight ended at a blank row and the answer ends at that row's content end; (b) a call that changes nothing (empty extent, or no runs over bytes already "no style, valid") returns before bumping `revision`; (a) the `CodeHighlightProvider` and `setHighlights` doc comments say either bound is fine and what covers a row.
- **Known ambiguity.** A partial answer through row r-1's newline, when r is the blank last requested row, is indistinguishable from the lineRange bound of r, and counts as covering it.
- **Tests** (`Tests/MetalUITestingTests/CodeViewTests.swift`): `aBlankRowAtTheVisibleBoundaryIsAnsweredByLineBounds`, `blankRowsInTheMiddleAndAtTheEndAreAnswered`, `anAnswerThroughTheNewlinesStillWorks`, `aPartialAnswerAsksAgainForTheMissingRows`, `aHighlightCallThatChangesNothingDoesNotRedraw`. Against the unfixed source the first, second and last fail (6 asks in 6 frames; an empty range and a repeated call redraw); the other two are guards that pass before and after.
