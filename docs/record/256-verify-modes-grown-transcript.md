# 256. Master failed both verify modes: a retained record with a hole (`RK-AF`, `BM-M`)

Branch `fix/markdown-verify-modes`, from master `50d8742c`. `METALUI_VERIFY_RETAINED=1` trapped in `indicesAreStableWhileTheDocumentGrows` (`replay differs from a fresh run … scene.count 6 vs 16`, which truncates the run) and `METALUI_VERIFY_LAYOUT_MEMO=1` failed three tests with six issues.

- **The suspect was innocent.** PR #247 (G15, `BM-L`, the copy button, `phaseAnimator`) is where the trapping test arrived (`36881e55` traps; checked), but with the button off and no prefix the same growth traps (a three-variant probe: no button, button without prefix, prefix without button, all trapped), and swapping the `phaseAnimator` for one phase changed nothing. The test was the first to grow a retained document inside a verifying window.
- **Root cause, a product bug (`RK-AF`).** Appending whole blocks to a transcript moves the earlier blocks; each is a grafted `.equatable()` occurrence whose prepaint key misses, so `EquatableComponent.prepaintGroup` requests a redo and its paint returns drawing nothing. The enclosing `MarkdownView` occurrence kept recording and `finishRetainedPaint` stored a record of only the new blocks. In a plain run the redo and every later frame replayed that record: a grown window drew 2 glyphs and 2 rects where a fresh one drew 8 and 4 (the earlier blocks vanished). Verify mode only noticed. Fix: the three early returns of `EquatableComponent.paintGroup` call `RetainLog.noteRedoHole()`, marking every open recorder; `finishRetainedPaint` returns for a marked recorder, storing and comparing nothing; the redo records the occurrence whole. (A first version skipped every record of an abandoned frame and failed `aMovedOccurrenceCostsOneMissAndTheNextFrameHits` and `theKeyOnlyArmCostsOneMiss`: h4 m4 became h2 m6.)
- **The three layout-memo failures (`BM-M`) are not regressions.** They count bytes the text system shaped, which verify mode recomputes by design; they fail identically at `36881e55^` (before G15). Gated `!rsVerifying && !layoutMemoVerifying` with the reason, as `AnimatableComponentTests` does.
- **Test.** `aTranscriptThatGrowsByBlocksDrawsWhatAFreshWindowDraws`, ungated (it reads what is drawn, so it runs in all three modes). Mutation (the `redoHole` early return removed, applied alone): that test red (`glyphs 2 vs 8`, `rects 2 vs 4`), and `indicesAreStableWhileTheDocumentGrows` traps again under `METALUI_VERIFY_RETAINED=1`.
- **Counts.** 2026-11-09, default build system, unfiltered `--no-parallel`, summed over the printed `Test run with` lines: plain 5763 passed, `METALUI_VERIFY_RETAINED=1` 5763 passed, `METALUI_VERIFY_LAYOUT_MEMO=1` 5763 passed, 0 `✘` in each (guards skip under the default build system; native not re-run). The three closeout probes print nothing.
