# 377 - The snippet session, keys and paint (`CV-BQ`, `CV-BR`)

Branch `feat/code-snippet-session` on `feat/code-snippet-model` (PR 378, `CV-BP`). Class M, no divergence (labels untouched). Second PR of the snippet work (Alloy code-intel #1). Alloy's answers bound it: `replacing:` at the primary only (the at-every-selection overload of the design is not built), a snippet inserted during a session ends the outer one, the indent unit is the view's when none is given, the model's fallbacks are enough.

**API.** On `CodeSelectionState`: `insertSnippet(_:replacing:indentUnit:)`, `isSnippetActive` (observable), `nextSnippetPlaceholder()`, `previousSnippetPlaceholder()`, `endSnippet()`; `CodeTheme.snippetPlaceholder: Color?` (defaulted `init` parameter). Package: `SnippetSession`, `CodeSelectionState.snippet`, `viewIndentSpaces`.

**Mechanism.** The session is a value on the state holding live placeholder ranges; while a group is current the selections are its ranges, so mirrors are multi-caret edits and every existing path (typing, deletion, coalescing, `replaceSelections`) applies. `CodeBuffer.moveStates`, both the scalar and the batch overload, calls `state.moveSnippet` behind a nil check; the batch overload replays the run's edits in application order (descending: highest first in their own coordinates; ascending: each shifted by the ones below). The move rules (current group grows at its edges, others hold, covered ones are removed, an empty one at the insertion point keeps its side, an ancestor of the absorbing placeholder grows with it) are in `CV-BQ`. `performUndo` ends the session of the group it pops by `CodeTransactionID`.

**View.** `CodeEditSession.run` asks the state first for Tab and ⇧Tab and for Escape (before the `CV-BI` collapse); `Window` already runs `onKeyPress` before the session. `CodeViewPlan.makePlan` writes the view's indent (`tabWidth` spaces or a tab) onto the state, unobserved, and copies the session into the plan only when `isSnippetActive`. Paint tints the non-current placeholders per shown row (binary search plus the parent chain, no per-frame work for a view with no session).

**Design notes.** The design said the indent unit would be taken from "the view"; the state has no view, so the view writes it (the one place that knows both). A multi-caret session needs no special case: the same index across carets is just several placeholders of one group, but the multi-caret insertion is not exposed. The empty-placeholder side rule and the parent-grows rule exist because the first version of the model lost nesting under typing at a shared edge; both have tests.

**Costs.** `noSessionMovesStatesExactlyAsBefore` pins that the number of state moves does not change with a session on another state; the existing multi-caret keystroke literals (`aKeystrokeFrameCostsWhatItDidWithOneCaretWhateverTheCaretCount`) are unchanged; `aKeystrokeInASessionCostsAPlainKeystroke` pins 1 request, 0 hits, 1 miss, 0 ineligible, 1 frame (Apple platforms; per frame elsewhere) with one and three mirrors.

**Tests.** `CodeSnippetSessionTests` (buffer module) and `CodeViewSnippetTests` (view, keys, paint, cost); the key list test gained the new conditions. Mutations are recorded in each file's header. Human check `CV35`.
