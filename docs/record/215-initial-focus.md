## 2. What changed

`FocusRegistry` keeps the best seat candidate (`bestSeat`, its top and its tree-order ordinal): `noteSeatCandidate(id:top:)` takes the smaller `top`, the first on a tie; `noteSeatHolder()` records the first `List`. `Frame.registerHandlers` notes an element whose handlers are `focusesOnPress` (the click-focus predicate: `.automatic` or `.edit`, so controls, `.activate` and text fields are out), inside the `enabled` and `keyboardVisible` gates, **outside** `hitTestingDisabledDepth` (`I26`) and only when `Frame.listRowDepth == 0` (pushed by `List.prepaint`; `ScrollView` content is a candidate). `List.prepaint` also calls `FocusRegistry.noteSeatHolder()` (same gates): `initialSeat` is nil when the first holder was noted before the winner (`I13`..`I13v`). `top` is the rect's top after the open render effects (`prepaintEffects.last?.composed.boundingBox`), so `.offset` counts (`G1`). Nothing is journalled: a replay notes none, and the first frame replays nothing, so the prepaint fingerprint is untouched. `Window.seatInitialFocus(from:)` runs right before `reconcileFocusStates()`: once (`initialFocusSeatSettled` flips whether or not a candidate exists, `L1`), only if `focusedElement == nil`, assigning `focusedElement` and calling `setNeedsRedraw()` once so the ring paints. **No `StateTable` write** (the next frame's `registerHandlers` writes `$focus` as for any focus), **no platform change** (it lives in `Window`: AppKit, SDL and headless agree), **no harness flag**. Doc comments: `FocusState.swift`, `TestWindow.swift`.

## 5. Behaviour changes for callers

The first `.focusable()` (or `.edit`) of a window holds focus after its first draw (ring, `onKey`/`onKeyPress` hear keys, `@FocusState` reads it one frame later), so a first Tab reaches the second stop and `TestWindow.focusedElement` is set after `init`. A launch-visible `TextField` takes no focus. A `ScrollView`'s content is seated by position (SwiftUI's); a `List`'s rows are not, and nothing after a `List` in tree order is. A focused `.focusable()` that is removed clears focus (217). Demos: the key-focus demo's viewport now holds focus at launch.
