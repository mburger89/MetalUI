## 2. What changed

`Text.prepaint` and `ProposalText.prepaint` call `Frame.registerTextLinks` for a `Text` whose content has a link run (`Text.hasLinkRun`: one `contains` over the runs; a plain `Text` pays nothing else, pinned by `aTextWithoutALinkDoesNoLinkWork`). It resolves the runs as paint does (`resolveRichText`), lays them out with the same call at paint's own origin, width and height (`Text.glyphBox(in:node:bounds:)`, now shared by `Text.paintGlyphs`; the plan's stop condition "prepaint cannot get the paint width without a second measure path" did not fire: `measuredWidth`, `lowering.textLeaves` and `bounds(of:)` are `Frame` state layout already set), and registers each `TextRunSegment` of a link run through `registerHandlers` as `minX`..`maxX` by `y + line.top`, `line.height`, with `onClick` and `PointerAttachment.style(.link)`, under `GlobalElementID.child(of: id, at: run, name: "$link<run>")`. One accessibility record per run through `recordAccessibility` (the `.isLink` trait, the run's text as label, the union of its pieces' rects), only while a client collects. `Text` registers inside `registerAndScope`'s content closure so the decoration's clip scopes it. `TextRunPaint` gained `link` so neighbours of different destinations stay two runs. New `OpenURLAction.swift`: `OpenURLAction(handler:)`, `.Result`, `callAsFunction(_:)`, `EnvironmentValues.openURL` (a custom key written through the public subscript, so uncomparable), and the internal `URLOpener` / `URLOpenerKey`. **`Window` stamps the opener, not a default action** (the plan's wording): a stamped `OpenURLAction` would be an uncomparable reading at the root and would make every `.equatable()` subtree of every window refuse retention; `URLOpenerKey` carries an identity reading, and `openURL`'s getter puts the opener on whatever action it returns. `PlatformWindow.openURL(_:) -> Bool` (defaultless): AppKit `NSWorkspace` after a scheme check, SDL `SDL_OpenURL` through `mui_open_url` after the RFC 3986 scheme check, headless `openedURLs`. 15 conformers: AppKit, SDL, headless, `FakePlatformWindow`, `PortableFakeWindow` and 10 compile-guard fixtures (9 files plus the `InputAPISeamCompileGuards` helper, which gained an `openURL:` parameter and a new guard `aPlatformWindowWithoutOpenURLDoesNotCompile`).

Docs: 150 retired (row, header, Retired, record 04, record 05's inert list, the inventory map's `attributed-text` family), 218 added, `docs/rules/text.md`, `tooling.md`, `sdl.md`, `decision-prefixes.md`, `docs/api-overview.md`, `docs/testing.md`, `docs/migration.md` (two rows), `CLAUDE.md` and `AGENTS.md` (the defaultless list, 208 live and next label 219, group `LI`), human group `LI`, `Tasks.md` (a sub-item, `(PR #TBD)`), the inventory map (family `open-url`, two M rows), and `RichTextDemo.swift`'s note.

## 5. Behaviour changes for callers

A link run in a `Text` opens its URL on a click (a window that showed link-styled text now opens a browser). A `Text` with a link adds a click hitbox and a pointing-hand region per piece and an `AXLink` child per run. A third-party `PlatformWindow` conformer must add `openURL(_:) -> Bool` (`docs/migration.md`). A subtree below `.environment(\.openURL, _)` is evaluated each frame. **`file:` and other app-launching destinations reach the platform like any other URL** (SwiftUI's `openURL` does the same): only a string with no scheme is refused (AppKit `workspaceURL(for:)`, SDL `hasURLScheme`). `LI-` says so in its "Carried" section: an app that renders untrusted text installs an `OpenURLAction` that filters.
