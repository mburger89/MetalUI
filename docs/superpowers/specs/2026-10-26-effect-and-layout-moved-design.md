# FS-O: retained replay when the layout moved and the outer effect changed together

Status: design (Designer phase), branch `perf/effect-and-layout-moved` from `aad9faf4`. Rulings: `docs/superpowers/2026-10-26-effect-and-layout-moved-decisions.md` (`EL-`).
Value-identical, **no public API, no divergence expected** (labels 865-874 reserved, none taken), no shader change, no `Backends/SDL` change.

## 1. The item and what is built today

An `.equatable()` occurrence under a render effect (`.scaleEffect`/`.rotationEffect`/`.offset`) is replayed in two independent ways:

- **Effect arm** (`RK-G`/`RK-S`/`RZ-`): rects equal, only the outer effects' numbers changed. Paint: `retainedPaintDecision` sees `key.differsOnlyByEffectAffine(from:)`, the record's leaves (recorded **before** any outer scope applies, `RZ-A`) re-enter the live scopes through `processScopes`. Prepaint: `retainedPrepaintDecision`'s `differsOnlyByEffects` branch, hitboxes via `translatedHitboxes(of:by:)` (current inverse, `AT-F`; `RL-I` chain walk), accessibility via `translatedAccessibility` (`AT-A`), geometry via `translatedGeometryNotes` (`RL-E`), anchors and context menus by `windowShift` only for a pure translation (`MA-H`).
- **Layout arm** (`FS-D`..`FS-P`, `RL-`): effects (ambient) equal, the first top node's origin and/or scroll offset moved by a whole-device-pixel exact delta. Paint: `key.shift(from:)` then `movedPaintRecord` (one add through `processScopes`). Prepaint: `ledger.key.shift(to:)` then `movedPrepaintLedger`, which refuses a hitbox that carries a transform (`hitboxUnderEffect`) and an accessibility record made under an effect (`accessibilityUnderEffect`).

Both relations demand the other part equal: `ReplayKey.shift(from:)` requires `ambient == old.ambient` modulo `offset`, `effectRelation(from:)` requires `rects == old.rects`; `PrepaintKey.shift(to:)` requires `ambient` and `extras` equal modulo scroll; the effect branch requires `rects ==`. A frame where **both** moved (a header above a zooming canvas grows) therefore matches neither arm: paint misses (an ordinary key miss, uncounted), prepaint runs. Only the pure-translation sub-case is counted (`effectAndLayoutMoved`, `RG-N`, one line in `retainedPrepaintDecision`); an affine + layout frame falls through silently (finding: the counter understates the gap).

## 2. Design: one combined relation, two existing moves composed in a fixed order

**Why it composes.** The record's leaves and the ledger's hitbox rects are in the occurrence's own pre-effect space: `(x + offset) * scale` with the layout origin, **before** any outer effect applies. The layout move is an add in that space; the effect is applied afterwards by the live scopes (paint) or by the current inverse/composed map (prepaint). So a combined replay is `effect_now( local + delta )`, the delta applied first, the effect second, and a fresh frame computes exactly that. The order matters whenever the scale is not 1 (`delta` under a scale `s` is `s*delta` in the window): applying the delta to the effect's output is the wrong-order mutation.

**Key relation (lane A).**
- `ReplayKey.shiftAndEffects(from old:) -> CombinedShift?` and `PrepaintKey.shiftAndEffects(to:) -> CombinedShift?` (internal, `RetainedTranslation.swift`). `struct CombinedShift { var shift: LayoutShift; var effect: EffectChange? }` where `effect == nil` means the effect scopes are equal (today's layout arm, which keeps calling the old functions unchanged: `shift(from:)`/`shift(to:)` stay and the new function **delegates** to them when no scope differs, so the existing arm's behaviour and pins cannot move).
- The shape half is `RetainedShape.shift` untouched (same node count, relative signature, sizes, relative origins). The ambient half: `ambient.scopes` normalised to the old key's where an `.effect` scope differs (the loop `effectRelation` already runs; factor it into a private helper `normalizingEffectScopes(_:against:) -> (AmbientKey, EffectRelation)` used by both, so the two relations read the same fields), `offset` normalised, then `== old.ambient`. The extras half: `PrepaintExtras.equalIgnoringScrollOffset` with `effects` blanked, then `extras.change(from:)` classifies the effects (`.translation`, `.affine`, `.refused(name)`). A `.refused` name is returned and counted by the caller exactly as `refuseEffect` does today (`effectFlatteningChanged`, `effectClipChanged`, `effectInverseChanged`, `effectScopeChanged`, `effectCountChanged`, `prepaintContextChanged`): the combined arm inherits all of them.
- Nothing is accepted when the layout shift is zero (that is the effect arm) or the effects are equal (that is the layout arm); both-zero is an exact hit.

**Paint (lane A).** In `retainedPaintDecision` a third case before the `moved` computation: `valid`, `old.key != key`, `memos.replaysPrepaint`, `memos.translatesLayout`, `key.shiftAndEffects(from: old.key)` with a non-nil `effect` -> `paintTranslation(of:shift:key:phase:)` (unchanged: `movedPaintRecord` reads only `key.rects`, `key.ambient.offset`, `key.ambient.clip`, `depths`, so the live effect numbers never enter the add). `moved` outcomes behave as the layout arm: `phase.translatedScene = moved.scene`, `translated += 1`, `old.key = key` (the **whole** key, effect numbers included, is sound because the stored scene is pre-effect and `finalScene` is nil whenever `ambient.scopes` is non-empty, `movedPaintRecord`), verify mode keeps `old.moved(to:)`. Every refusal of `movedPaintRecord` (`innerScope`, `fractionalTranslation`, `inexactTranslation`, `unlistedKind:*`, `transformedPrimitive`, `maskStraddlesEntryClip`, `unkeyedClip`) is inherited unchanged. A refused combined paint is a miss, as the layout arm's is. `EquatableComponent.paintGroup` replays through `frame.replayPaint(record, translated: true, scene:)` which already runs the leaves through the live scopes (the zoom arm's mechanism), so no renderer change.

**Prepaint (lane B).** In `retainedPrepaintDecision`, the `else if ... effectAndLayoutMoved` fall-through becomes a real branch evaluated when neither existing arm matched: `ledger.key.shiftAndEffects(to: key)` with both parts non-nil.
1. Effect classification: `.refused(name)` -> `refuseEffect(name)`. `.affine` with `!ledger.anchors.isEmpty` -> `presentationAnchor`; with `!ledger.contextMenus.isEmpty` -> `contextMenus` (as the zoom arm). **A pure-translation effect with a layout shift also refuses anchors and context menus** (`presentationAnchor`, `contextMenus`): the window shift of a window rect under a layout move is `L * delta` for the effect's linear part `L`, a third quantity `MA-H` does not carry (`EL-F`); they stay carried.
2. Refusals that need the occurrence's own space: `ledger.pressOnly` (as `movedPrepaintLedger`), a hitbox with `shape`, `scroll`, or the handlers `textInput/valueTrack/dropDestination/contextual` (the layout arm's four), and **any hitbox, accessibility record or geometry note whose chain has steps beyond the ambient** (registered inside an effect the occurrence opened): refused by the **new name `effectAndLayoutInner`** (`EL-D`: such an effect's own map is anchored at the occurrence's own position, so it changes with the layout shift in a way neither delta can name; paint already refuses it as `innerScope`).
3. Hitboxes: new `Frame.movedTranslatedHitboxes(of:shift:clip:entryDepth:)` (`RetainedTranslationCarries.swift`): per hitbox, add the **layout-window delta** (`shift.windowX/Y`, exact sixteenth gate `inexactTranslation`) to `bounds`, `origin`, `unclipped` in local space exactly as `movedPrepaintLedger` does (entry-clip cut recomputed for `clipDepth == entryDepth`, else strictly inside before and after, `hitboxClipped`), **then** run `translatedHitboxes`' per-hitbox rewrite (`transform.outerClip == outer`, `inverse == recorded` -> the current effect's inverse). The two are one loop over a shared per-hitbox helper (lane B factors it; `translatedHitboxes` keeps its signature and outputs byte for byte for its two existing callers).
4. Accessibility: record-local rects (`AXLocalRects.frame/clipped`) are moved by `(shift.windowX, shift.windowY)` with the hitbox rule for the clip, **then** `translatedAccessibility`'s recomputation against the current effect (`AT-A` arithmetic). Implemented as `shiftedLocals(of:dx:dy:clip:entryDepth:)` returning a ledger copy whose `local` rects moved, handed to `translatedAccessibility`. An emission or node with no `local` -> `accessibilityUnrecorded` (counted, as today).
5. Geometry notes: `note.moved` shifted by the window delta (exact sixteenth, `inexactTranslation`), then `remade(...)` with the current `prepaintEffects.last?.composed` (the `translatedGeometryNotes` arithmetic). A note that holds a named space refuses `geometryNamedSpace` (`EL-E`: a named space would need `L*delta` plus the effect delta, unmeasured; this is what `RZ-E` already does for affine).
6. Element bounds: layout rects, move by `shift.layoutX/Y` alone (the `FS-P` rule, unchanged).
7. Pointer: read against the **moved and re-derived** hitboxes (`Hitbox.contains` applies the transform), `pointerInMovedLedger` refusal, as in both arms (`FS-P`, `RZ-D`).
8. On success: `memos.ledgerMoves += 1`, `retained.prepaintHits += 1`, skipped prepaints counted, ledger **rebased** to the new key (`PrepaintLedger.rebased(to:_:)` copies `hitboxChains`, `axNodeLocals`: the locals must be the moved ones, `EL-G`) unless verify mode, where the old ledger is kept and compared (`RK-N`).

**The counter.** `effectAndLayoutMoved` is **retired** (never emitted again, like `effectNotTranslation`), replaced by the named reasons above. A refusal combined from the layout half (`fractionalTranslation`, `inexactTranslation`, `hitboxClipped`, ...) keeps its own name.

**Graft (`RK`).** An occurrence whose paint and prepaint replay is grafted by the existing machinery under the unchanged `BuildKey`; nothing in the graft decision reads the shift relation, so the combined arm needs no graft change. The spec's pin `T6` proves it (grafts 0 -> 6 across the combined frame) and the plan owns the finding if the graft site refuses (`translationUnderEffect` style name) and reports it rather than widening scope (`EL-H`).

**Inherited vs retired refusals (the item's list).** Inherited unchanged: `effectFlatteningChanged`, `effectClipChanged`, `effectInverseChanged`, `effectScopeChanged`, `effectCountChanged`, `prepaintContextChanged`, `geometryNamedSpace`, `presentationAnchor`, `contextMenus`, `accessibilityUnrecorded`, `innerScope`, `fractionalTranslation`, `inexactTranslation`, `hitboxClipped`, `hitboxShape`, `hitboxScrolls`, `hitboxHandlers`, `pressOnly`, `pointerInMovedLedger`, `unlistedKind:*`, `transformedPrimitive`, `maskStraddlesEntryClip`. New: `effectAndLayoutInner`. Retired: `effectAndLayoutMoved`, and `hitboxUnderEffect` / `accessibilityUnderEffect` are **kept** for the layout-only arm (an effect that did not change but a layout move under it: still refused there, by `EL-I`; lifting them for that case is a different item).

Expectation: with Retention on, a zoom step with a header step costs element requests ~5-6 and prepaints ~5-6 against 115/117 with the switch off (`EL-J`; numbers dated, re-taken at the Record phase). ## 7. Human checks (group `EL`, added at the Record phase to `docs/verification/human-checks.md`)

## 8. Deferred (named, with a reason and an owner)

| Item | Reason | Owner |
|---|---|---|
| Anchors and context-menu records under a combined move | their window rect moves by `L*delta` plus the effect's own shift; `MA-H` carries only a pure translation with a known delta; unmeasured | next retained item (`EL-F`) |
| Named space inside a combined note | needs `L*delta` composed with the effect delta, dyadic checks on both | `RL-E`'s carried "non-dyadic named space" item |
| An effect the occurrence opens, under a layout shift | the inner map is anchored at the occurrence's position; paint already refuses (`innerScope`); not a new gap | `effectAndLayoutInner` named, `EL-D` |
| Lifting `hitboxUnderEffect`/`accessibilityUnderEffect` for a layout shift under an **unchanged** effect | a different relation (the layout arm), same machinery; out of this item's scope | carried, `EL-I` |
| Surface, shadow, blur, gradient, path leaves under a combined move | still `unlistedKind:*` (`FS-M` allow-list) | `P3`-class pixel work |
