# `Table` (`TBL-`): implementation plan

> **For agentic workers:** carry this out task by task, one PR per lane. Planned by Opus on 2026-11-18 against master `91a9904e`. Read the spec first. Read `docs/practices/verifying-tests-can-fail.md` before writing any test.

**Goal.** Build a SwiftUI-shaped `Table` whose per-frame work depends on the viewport, never on the row or column count. It must cover 1 000 000 rows by 200 columns on macOS, Linux and Windows.

**Architecture.** The work is in five lanes:

- **A:** a pure two-axis window engine (`UniformWindow`, `ColumnExtentIndex`, `TableWidthSolver`, `TableWindowPlanner`) and its counters.
- **B:** the public types, rendered as an internal scroller over `TableBody`, with rows, cells, a pinned header and frozen columns.
- **C:** selection, keys, context menu and sorting, reusing `List`'s controller.
- **D:** column resize and reorder through `@State`.
- **E:** accessibility on the platform tree, AppKit and AccessKit.

**Tech stack.** Swift 6.4, Swift Testing, and `MetalUITesting` headless windows (harness text system).

**House rules for every task:**

- Write the test first and run it; it must fail.
- Implement, run, then apply the named mutation; the test must go red. Restore from a backup copy and check with `git status --short`.
- Read counts after `try await w.runUntilIdle()` and sum them over `w.frameWork`. Read a steady frame as `w.window.setNeedsRedraw(); w.tick(); w.lastFrameWork`.
- Use `Modifiers.primary` for toggle clicks.
- Portable tests go in `Tests/MetalUITestingTests/`. AppKit tests go in `Tests/MetalUITests/`. AccessKit tests go in `Backends/SDL/Tests/MetalUISDLTests/`.
- Every new public declaration gets a doc comment and an inventory row.
- Commits end with the session's attribution lines.

**Verification commands (every PR's last task):**

```bash
swift build && swift build -c release
swift build --build-system native --build-tests && swift test --build-system native --no-parallel
zsh docs/probes/closeout-inventory-check.sh      # prints nothing

cp CLAUDE.md AGENTS.md && cmp CLAUDE.md AGENTS.md
```

Then push and let CI's Linux and Windows jobs run. A red CI job is a stop condition.

**Shared fixtures**, in `Tests/MetalUITestingTests/TableFixtures.swift`, created in A5 and extended in B4:

- `struct Cell: Identifiable { let id: Int }`.
- `final class CountingRows: RandomAccessCollection` over `0..<n`. It returns `RowRef(id: i)` and counts `subscriptReads` and `countReads`. It is a class so the counts are shared. `Index == Int`.
- `tableFixture(rows:columns:frozen:)`: a `Table(CountingRows(n))` with `TableColumnForEach(0..<columns) { c in TableColumn("c\(c)") { r in Text("r\(r.id)c\(c)") }.width(Pixels(100)) }`, `.tableRowHeight(24)` and `.tableFrozenColumns(frozen)`, in `harnessWindow(size: sz(800, 600))`.
- `scrollTable(_ w:, x:, y:)`: sends one vertical then one horizontal phaseless wheel event at (400, 300) that move the offset by exactly (x, y), then `runUntilIdle()`. Take the delta sign from the two-axis scroll tests' helper. Use two events because a diagonal goes wholly to the dominant axis (`XS-F`).

### Task B3: the body and the header

**Files:**

- `Sources/MetalUI/TableBody.swift` (new): `TableBody<Value>`, `TableBodyLayout`, `TableHeaderRow`, `TableHeaderCell`, `TableColumnDivider` (no gesture yet; D1 adds it)

**What `TableBody.requestLayout` does, in order:**

1. Read `count` once.
2. Resolve the columns (O(C); `tableWork.columnsResolved += C`).
3. Compute the display order: the frozen keys, then `columnState.order`, then new keys in declared order.
4. Run the width solver with the viewport from `context.along(.horizontal)?.viewportExtent ?? 0`.
5. Build the `ColumnExtentIndex`.
6. Call `TableWindowPlanner.plan`.
7. Call `noteWindowedParent(id)`.
8. Push the environment `lineLimit = 1`, `.tail` once.
9. For each row in `plan.rows`, read `data[i]` once (`dataReads += 1`) and build its row element.
10. Build the header last.
11. Register `TableBodyLayout`.
12. Bump `rowsRealized`, `cellsRealized` and, on a cold plan, `coldFrames`.

**What `prepaint` does:**

1. Inside `frame.insideListRows`:
   - store `TableViewState` through `withState(…, unchanged: sameEntry)`;
   - compute `fresh`; if `!contains`, call `requestAnotherFrame()`;
   - prepaint the rows, then the header.
2. On a cold plan, wrap everything in `withAccessibilitySuppressed(except: id)`. PR E fills in the records.

## Review Focus: the five likeliest failure modes

1. **Hidden O(rows) work.** It hides in any `data.enumerated()`, `for datum in data`, `Array(data)`, or `List`-copied helper:
   - `List.resolveScrollRequests`;
   - `rowSpace.index`;
   - `accessibilityRowSelection`'s `byRow`;
   - `ListSelectionController.leadIndex`'s loop with an empty selection.

   On a paged source each of these faults in every page. `CountingRows` tests B5, C1, C2 and C5 are the guard: review every new `data[` against them.

2. **Pinned header and frozen-column placement.** They must come from the table's own **clamped** offset, not the raw `ScrollContext` offset. Pinned parts must be built, prepainted and painted last, and be opaque (paint and hitbox). The accessibility order must be restored by the builder's sort. A placement taken from the raw offset jumps for a frame on overscroll (B4 `anOverscrolledWheel…`). A wrong order lets clicks reach a scrolled cell under the frozen column.

3. **Identity under two-axis windowing.** Rows and cells must both call `noteWindowedParent`. A cell's name must come from its `TableColumnKey`, never its display position: a reorder, a column-set change or a horizontal scroll must not reset cell state. Cells must not be `Box`es: 280 `$anim` slots a frame churn the `StateTable`.

4. **An extra-frame loop that never settles.** The staleness check compares rows, columns, the widths digest and the pin offsets. Any oscillation keeps the display link awake and makes `runUntilIdle()` throw `notIdle`. Examples: the fill rule against a one-frame-stale viewport, float rounding in the pins, or a cold plan treated as containing. Likewise, a `TableViewState` written without an exact `unchanged:` comparator taints the table's retained ancestors every frame (`RW-I`). Tests: B4 cold, B6 idle, B6 settled-in-`.equatable()`.

5. **Reveal and accessibility arithmetic.**
   - A keyboard reveal must keep the horizontal band and clear the header. Otherwise ↓ jumps horizontally, or leaves the lead row under the header.
   - Page and End must resolve by position.
   - AccessKit's `row_count` and `row_index` must count the header row, while AppKit's must not.
   - Divergence 1107 (no `AXColumn`) must be the only AppKit gap a VoiceOver user meets.

   Tests: C2, E3 and E4, and human check TBL1/TBL2.
