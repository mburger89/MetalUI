# Clickable text links (round 4 item R4-4 PR D) — decisions (prefix `LI-`)

Rulings for divergence 150 (retired) and the new row 218. Branch `feat/text-links`, on `feat/initial-focus` (PR #211). Record 216. Evidence: the probe `docs/probes/swiftui-text-links.swift` (arm ids below; run three times, byte-identical, 2026-11-04, macOS 27.2, Swift 6.4.2, screen locked, no computer use; header records the output and what is not measured). The plan's arms were never committed; the probe rebuilds them from the plan's table and keeps its ids (`LK0`..`LK23`, `O0`..`O9`). Next unused id: `LI-H`.

## LI-A: a link run registers one click region per laid-out piece

1. **SwiftUI** (`LK0`, `LK1`, `LK3`, `LK16`): a link run opens on mouse-up on the run only; `AttributedString.link` and the Markdown literal behave alike. Press on and release off (`LK4`), press off and release on (`LK5`), a right press (`LK6`) and `.allowsHitTesting(false)` (`LK8`) do not open. A double click opens twice (`LK19`). A **wrapped** run opens only over its own pieces (`LK12` map: line 1 from the run's start to the line's end, line 2 up to the run's end, not over the text after it). A drag inside the run **opens** (`O9`, `O9b`, `O9c`, with the control `O9d` proving the drag events arrive): **the plan's reading ("a 25 pt drag inside the run does not open") is not reproduced**, and MetalUI opens too, so there is no drag half of row 218.
2. **MetalUI**: `Text.prepaint` and `ProposalText.prepaint`, **only for a `Text` whose content has a link run** (`Text.hasLinkRun`, one `contains`), resolve the runs, lay them out with the same call paint makes (`Frame.registerTextLinks`) and register each `TextRunSegment` of a link run: `minX`..`maxX` by its **line's** box (`y + line.top`, `line.height`), as `drawStyledText` fills backgrounds. One numbered child id per resolved run (`$link<n>`), so a press on one piece and a release on another of the same run opens (a bidi run has several pieces under one id). Each region goes through `registerHandlers` (`onClick` plus the pointing-hand style), so the disabled, `allowsHitTesting`, clip and translation gates are the ordinary ones, and `Window.dispatchClick`'s topmost-opaque-hitbox-with-the-pressed-id rule gives `LK4`/`LK5`/`LK6` for free. **A plain `Text` does no extra work (`RT-M`)**: it pays the `contains`; pinned by the work count `aTextWithoutALinkDoesNoLinkWork` (an unlinked styled text lays out once, a linked one twice and reads the environment once more).
3. **The paint width is available in prepaint, no second measure path.** `Text.paintGlyphs` read `pass.measuredWidth(of:)` (`frame.tree.measuredWidth(frame.lowering.alias(node))`), `Frame.lowering.textLeaves` and `bounds(of:)`, all `Frame` state set by layout; the stop condition did not fire. The computation is now one function, `Text.glyphBox(in:node:bounds:)`, called by paint and prepaint, so the two agree by construction. `ProposalText` reads `measuredWidth` and its bounds in both.
4. Link regions register in `registerAndScope`'s content closure, so the decoration's clip scopes them as it scopes a child.
5. **A destination `URL` cannot parse registers nothing.**
6. **Ranking** (read through `O0`..`O6b`): the link beats a tap on the `Text`, on an ancestor and a `Button` label (`dispatchClick` finds one topmost opaque hitbox, the link's, so the ancestor tap does not fire: the stop condition on `IX-D` did not fire); off the run those fire. An overlay tap above the text wins (`O5`). `simultaneousGesture(TapGesture)` fires both, the tap first (`O6`), and `highPriorityGesture` the tap only (`O6b`); MetalUI agrees on both.

## LI-B: a run's link is part of its paint record

`TextRunPaint.link`: two neighbours of one style and different destinations stay two runs (each with its own region), and a link run never joins a plain neighbour that happens to share its colour. The link is not part of the layout style, so `StyledText` and its measurement are unchanged.

## LI-C: `OpenURLAction`, `.Result`, `EnvironmentValues.openURL`

1. **SwiftUI** (`LK15`, `LK14`, `LK14b`, `LK20`, `LK21`): the nearest `\.openURL` runs; `.discarded` ran the handler and an **outer** action did not run after it; a custom scheme and a scheme-less destination (`example.com`) reach the action as written.
2. **MetalUI**: public `OpenURLAction(handler:)`, `callAsFunction(_:)`, `.Result` (`.handled`, `.discarded`, `.systemAction`, `.systemAction(_:)`) and `EnvironmentValues.openURL`. The handler is `@MainActor (URL) -> Result`. `.handled` and `.discarded` ask the platform for nothing; `.systemAction` asks for the link's URL, `.systemAction(url)` for `url`. The key is a custom `EnvironmentKey` written through the public subscript, so its reading is **uncomparable**: a writer refuses retention at its position (`EE-`, divergence 346 narrowed), an `.equatable()` subtree below `.environment(\.openURL, _)` is evaluated each frame and a changed action is never stale (`aChangedActionAboveAnEquatableSubtreeIsNotStale`; the mutation that makes the key comparable reddens it).
3. **Not measured**: what `.systemAction` and `.discarded` do after the handler ran (the probe never opens a browser). MetalUI's reading of `.discarded` is SwiftUI's documented one (the system does nothing).

## LI-D: the platform seam and the window's default

1. **`PlatformWindow.openURL(_ url: String) -> Bool`, defaultless** (`CI-J`'s reason; guard `aPlatformWindowWithoutOpenURLDoesNotCompile`). AppKit: `NSWorkspace.shared.open`, after refusing a string with no scheme (`AppKitWindow.workspaceURL(for:)`). SDL: `SDL_OpenURL` through `mui_open_url`, after the same scheme test (`SDLWindow.hasURLScheme`, RFC 3986: no scheme, no call; a leading `-` or a bare word never reaches a platform's URL handler); `SDLWindow.openURLRequest` replaces the native call in a test. Headless (`HeadlessPlatformWindow`, `HT-X` 1): records `openedURLs` and answers `true`. 15 conformers: AppKit, SDL, headless, two fakes and the compile-guard fixture strings.
2. **The default action is not a stamped `OpenURLAction`.** The plan had `Window` stamp a default action capturing the platform window weakly. A stamp on the root environment, written through the public subscript, is uncomparable and would make **every** `.equatable()` subtree of every window refuse retention. Instead the root stamps an internal key, `URLOpenerKey`, holding a `URLOpener` (a class that holds the platform window **weakly**) with an **identity reading** (`EnvironmentReading.object`), and `EnvironmentValues.openURL`'s getter puts the opener on whatever action it returns (the system default, or a user's). A user action's `.systemAction` therefore reaches the platform as well, and `@Environment(\.openURL) var openURL; openURL(url)` works off a link. Pinned: `theDefaultActionHoldsThePlatformWindowWeakly` (the opener does not keep the window alive and opens nothing once it is gone), the retention pins, and the identity reading costs nothing.
3. **No test reaches `NSWorkspace` or `SDL_OpenURL`**: the fake records, the AppKit test stops at the refusal, the SDL test replaces `openURLRequest`.

## LI-E: accessibility

1. **SwiftUI** (`AX1`, `AX2`): the `Text` stays `AXStaticText` with its whole string as the value; each link is an `AXLink` child with a label (`aa`, `bb`) and its own frame; a wrapped run is **one** link element framed by the union of its pieces (`LK12`). The link element publishes five attributes (role, role description, parent, window, top-level element), **no `AXURL`**, no actions and no custom actions; its press is not reachable in-process (`accessibilityPerformPress` raises). What VoiceOver does with it is not measured (human check `LI3`).
2. **MetalUI**: one accessibility record per link run through `Frame.recordAccessibility` (a synthesized record, so no `axNodes` entry and no `$ax` slot, `AB-U`), declared with the `.isLink` trait and the run's text as its label, framed by the union of its pieces' rects, under the run's id, a child of the text's id. Its press is derived from the link's hitboxes like any other (`AB-H`). **No new `AccessibilityNode` field**: the probe shows `AXURL` is not published, so the stop condition did not fire. The record is made only while a client collects.

## LI-F: the pointing hand

Each link region carries `PointerAttachment.style(.link)`, a non-opaque region that blocks no click (`CI-H`). **Inferred from platform behaviour, not probed** (a synthetic `mouseMoved` does not change `NSCursor.current`); a person confirms the look (human check `LI1`). `aLinkRegionCarriesThePointingHandStyle` pins what the window asks the platform for.

## LI-G: divergence 150 retired; new row 218 (`.disabled`)

150 is retired (the label is not reused). **Row 218**: `.disabled(true)` still opens a link in SwiftUI (`LK7`) and inside a disabled `Button`'s label (`O3`); MetalUI's one disabled gate (`Frame.registerHandlers`, `EV-E`) withdraws every handler region, so a disabled link is inert and no accessibility link is published. Pinned wrong on purpose by `aLinkUnderDisabledIsInertWhereSwiftUIOpensIt`. Making a link ignore the disabled gate would need a registration path outside `registerHandlers`; it was not done (`registerHandlers` is the rule's one gate and the D2 guard's arm), so the row stays. A drag inside the run is **not** a divergence (`LI-A` item 1).
