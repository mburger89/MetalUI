## DS-B: the default spacing at a text edge, as measured (input to PR B; no design chosen)

The numbers below are SwiftUI's on macOS 27.2, read by three instruments that agree to the printed 0.001 on all 922 pairs. They are facts, not rulings; PR B decides what MetalUI does with them.

1. **Horizontal gap: 8** beside every neighbour, at every font, size, style and wrapper measured (stop condition 6 did not fire).
2. **Vertical gaps are a function of the resolved font's metrics** (CoreText ascent a, descent d, capHeight c, leading l; 107 rows over SF, serif, mono, rounded, Georgia, Menlo, Noto Sans, Source Sans 3, ArialMT, Futura, DIN Condensed, Geneva, sizes 6 to 200 with fractions), residuals as the probe prints them:
   - rect above text: `d + ceil((a + d) / 10)` (residual 0.0000)
   - text above rect: that `+ (a - c)` (residual 0.0010, the print's third decimal)
   - text above text: `ceil(l)` of the LOWER text (residual 0.0000): 0 for `.system(size:)` and an unset font, a whole point for a text-style font (`.body` 1, `.title3` 3, `.largeTitle` 2, ...), which carry NSFont's preferred-font leading.
   Rejected by the same data: a constant (H0), a gap proportional to size (H1), `a / 8` or `floor(a / 8) + 1` for the step (fail at 16.9, 24.9, 25, 200 and Geneva 48), a rule without cap height for text-over-rect (H2: up to 9.3 pt off).
3. **Closed rule: yes** (stop condition 3 did not fire). **It needs a metric `TextFontMetrics` lacks** (stop condition 5): `capHeight`. `ascent`, `descent` and `leading` exist (macOS: `CTFontGetAscent/Descent/Leading`; portable: `hhea`, equal to CoreText's to three decimals for both `Tests/Fonts` faces, whose cap heights are 714 and 660 per mille in `OS/2` but are not read by `MetalUIFreeType`). The text-style leading is not expressible either way: MetalUI resolves a text style to a size and weight of the plain system font (`Font.swift`), whose leading is 0, where SwiftUI's carries the preferred font's. Nothing was added to `TextFontMetrics` in this PR.
4. **Edges are not just zero, standard and text** (stop condition 8, to be decided): beyond text, a `.plain` text `Button` and a `Label` are text edges; a checkbox `Toggle` is 6 beside a rect and a toggle; an SF Symbol `Image` is 2 above and 3 below at 13 pt (and 0 against text and itself); a fixed frame and non-zero padding turn the affected edges standard; an empty `Text` has none. Unions: text beats standard, the larger font's edge beats a smaller, a nested stack or Grid passes its first and last child's edge along its axis, a lazy stack and a one-column lazy grid follow the same rule as `VStack`, a `ScrollView` as a child is standard.
5. **Leaf-only capture is consistent with the data** (stop condition 7 did not fire): a font set on the stack is inherited by its Texts and changes nothing else (rect|rect 8, Button 8, Toggle 6). `displayScale` as an environment value, `dynamicTypeSize` and `controlSize` (beyond the default font it selects) change nothing (stop condition 4 did not fire); a real backing scale was not measured (screen 1.0 only).

## DS-E: the default vertical gap at a text edge (PR B; implements `DS-B` item 2 on macOS)

1. **One pure function** decides every default gap: `ProposalSpacing.defaultGap(after:before:axis:)` (`MetalUILayout`, `package`). With a = ascent, d = descent, c = capHeight, l = leading of a text's resolved font: a zero edge on either side 0; **horizontal 8**; standard above text `d + ceil((a + d) / 10)` of the lower text; text above standard that `+ (a - c)` of the upper text; text above text `ceil(l)` of the lower text; anything else 8. `Spacer()`'s nil minimum stays the constant 8 (`DS11`), an explicit spacing stays verbatim, a pair of non-text views stays 8.
2. **The metrics are captured when the text leaf registers**, never in a layout phase: `Text` and `ProposalText` (plain and styled, four sites) read `system.fontMetrics(key)` through the seam and hand the tree plain doubles (`TextSpacingMetrics`, `MetalUILayout`; no text module, no `Style`). A styled text takes the metrics of the largest of its runs' fonts (`DS6` `mixedSum`). An empty string has a zero vertical edge (`DS6` `empty`: 0 above and below, 8 beside it).
3. **The font is the resolved font**, so a font set on the stack reaches its texts and changes nothing else (`DS10`); the environment is read at the leaf, as before. The marks live in `LayoutTree`'s `spacingMarks` table (a node index to a `SpacingEdge`), cleared by `reset`, carried by `LayoutSegment` and its graft, shown in `structureDigest`, and mixed into `nodeSignature` **for marked nodes only**, so every unmarked signature is bit-identical to what it was. A `.standard` mark records nothing.
4. **The gap is exact, not quantised** (plan section 2): `4.742`, `8.151`, `9.484` stay fractional in the measured lengths; placed rects are rounded as before. The memo and translation counters did not move (record 203 section 5), so the 1/16 quantisation the plan held in reserve was **not** taken.

## DS-F: `TextFontMetrics.capHeight`, and the rule on Linux and Windows (PR B; the user's rulings 1 and 2)

1. **Stop condition 5 was resolved by adding the field** (`DS-B` item 3): `public let capHeight: Double?` on `TextFontMetrics`, the initialiser gaining a defaulted `capHeight: Double? = nil` (a third-party `TextSystem` conformer still compiles; `nil` means no cap term, so text above rect equals rect above text for that font: the kernel stores `capHeight ?? ascent`). CoreText fills it from `CTFontGetCapHeight`; the portable system from `OS/2.sCapHeight` through FreeType (`FreeTypeFont.capHeight`, `package`, version 2 and later, else `nil`; scaled by `size / unitsPerEm`). Noto Sans reads 714 and Source Sans 3 660 per mille, equal to CoreText's at 13 pt (9.282 and 8.58). It is a new stored property on a public type crossing a module boundary: `swift package clean`.
2. **MetalUI applies the same rule on Linux and Windows, with those platforms' own metrics (`hhea` ascent, descent and leading, `OS/2` cap height).** This is **MetalUI's ruling, not a measured claim**: SwiftUI cannot be measured there. The macOS figures hold for `Tests/Fonts` because `hhea` equals CoreText's for both faces to three decimals (record 202 section 2), so `rect|text` reads 5.809 and 6.238 at 13 pt there too; a face with other `hhea` and `OS/2` numbers gets the rule's answer, which no SwiftUI reading checks.
3. **The text-style leading is not expressed** (row 214): MetalUI resolves `.body` and the other styles to a size and weight of the plain system font, whose leading is 0, so text above text is 0 for every font MetalUI offers; SwiftUI's `.body` reads 1, `.title3` 3, `.largeTitle` 2 (`DS4b`). A table of the eleven styles' ceil'd leadings (2, 1, 2, 3, 1, 2, 1, 1, 2, 2, 2) is not worth shipping.

## DS-G: three edge kinds, and the unions (PR B; the user's ruling 3, stop condition 8)

1. **Zero, standard, text**; no category system. The kernel's `zeroSpacingEdges` became `spacingEdges` returning a `SpacingEdge` per edge. Text edges exist on the vertical axis only (a marked node answers `.standard` horizontally, `DS1`).
2. **Unions** (`DS8`, `DS9`): along the axis a stack or grid passes its first child's leading edge and its last child's trailing edge; across it (and for a custom layout) a zero child makes the composite zero, else the text edge of the **largest font** (by `ascent + descent`) wins over a standard one; a `ZStack` is zero only when every child is, else the same union of the rest. A fixed-height `.frame` (`height != nil`) and a non-zero inset give a text edge the standard one, on the edges they touch; zero padding, horizontal-only padding, flexible frames, `fixedSize`, `layoutPriority`, background and overlay pass the edge through. **A width-only fixed frame is treated as passing** (the probe's fixed frame has both dimensions): unmeasured.
3. **A grid's cells carry the same edges** (`NativeGridEdges` holds `SpacingEdge`s); a pair's gap is `defaultGap`, the row gap the largest pair over the cells meeting in a column, the column gap 8 (`DS12`), a grid as a stack child its first and last rows' edge. This is why **65 retired**: the grid arms fit the stack rule.
4. **Not expressed: a rect-and-text composite beside a text** (stop condition 8, reported, not improvised). `HStack{rect; text}`, `ZStack{rect; text}` and `Pass{rect; text}` read like a text edge beside a rect (the three-kind union agrees: 4.742 and 8.151) **but like a standard edge beside a text** (`DS9` `hstackRectText`: M|text13 4.742, text13|M 8.151, M|text26 9.484, text26|M 16.302), where the union reads text over text: 0 and 0. Closing it needs a fourth, mixed edge kind. It is pinned as the ruling reads it (`aMixedCompositeBesideTextIsPinnedAsTheRulingReadsIt`) and recorded in row 213.

## DS-H: controls keep a standard edge (PR B; the user's ruling 4)

1. **The plan's suppression flag was replaced by a node mark with the same effect.** A flag set while a control registers its label would also strip the text gaps *inside* the control's own label (a `Button` whose label is a `VStack` of two texts); a mark on the control's root node (`LayoutTree.markControlSpacing`, `spacingMarks[id] = .standard`) makes the walk see the control as a unit and leaves what is inside as the text rule makes it. Both give the plan's tests the same readings.
2. **Marked standard:** a bordered, bordered-prominent, glass and glass-prominent `Button` (the automatic style resolves to bordered), a `Toggle` in every look (the checkbox 6 is row 213), `Stepper`, `Picker` in every style, `ColorPicker`, `ProgressView`; `Slider` and `TextField` register no text leaf and are standard by being leaves. **Text edges:** a `.plain`, `.borderless` or `.link` `Button` (the label alone, `BT1`), as DS7 measures. A custom `ButtonStyle` or `ToggleStyle` is the caller's body and is not marked. MetalUI offers no `Label`-shaped spelling, so there is none to take text edges.
3. **`everyControlKeepsAStandardEdgeBesideText`** enumerates twenty controls and looks with `try #require` on the count; a new control owes an arm and a `markControlSpacing`.
