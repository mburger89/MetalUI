## ER-A: an `AnyElement` is keyed by its wrapped type (retires 210; overturns `FV-C` item 3)

1. **SwiftUI** (probes): an `AnyView` whose wrapped type changes is a new element. State resets, written or not (`D5`, `D5b`); a swap back starts fresh, there is no revival (`AV1`: A written 11, B, A reads 10); focus drops and does not return (`AVF`); the old `.task` is cancelled and the new one started
   (`AV5d`); `onAppear` and `onDisappear` fire once, `onDisappear` reads the value the old content left with and its write is lost (`AV5a`, `AV5b`); a modifier outside the `AnyView` fires nothing (`AV5c`). The same wrapped type keeps everything (`AV1b`, `AV2`, `AV3c`, `AV3c2`); `Gen<Int>` and `Gen<String>`, and `VStack`/`HStack` around one leaf,
   are different types (`AV3a`, `AV3b`); a nested `AnyView` resets only what changed (`AV4a`, `AV4b`).
2. **The design.** `AnyElement`'s group entry lays the wrapped element out, binds it and runs prepaint and paint under `T = child(of: P, at: 0, name: ElementID(name: "$erased", key: IdentityKey(AnyHashable(ObjectIdentifier(E.self)))))`, where `P` is the position's id as before, and calls `noteNamed(T, at: 0)` on every build. The position keeps its
   own `noteNamed` and its `recordElementBounds` (so `scrollTo` and `frame(ofID:)` still find a named element at `P`). That is all: `noteNamed` departs the old `T` at the position `(P, 0)`, `sweep()` deletes everything at or under it (`ID-R`, `resetQueuedEntries`; `$ax` is exempt), and the existing `.named` journal event replays it in `Frame.reapply`,
   so a graft keeps the position's previous name. `T` holds no entry and is not an eighth retention slot; its key makes it unspellable (`.id("$erased")` has a nil key and cannot collide). `$toolbar` and `$menubar` are the precedents for a named level holding no entry. No new table, reset path, journal case, public declaration or `StateTable` write site.
3. **Why not the type-keyed id alone (record 199's M15).** It gets the first swap right and fails afterwards: an unmarked `T_A` entry survives every sweep below the reap threshold (256 entries), so A's 11 comes back on a swap back (the revival `AV1` refutes); `onDisappear` gets no overlay, so a write there lands in the real table; focus clears a frame late; and placed in `AnyElementBox` it
   would rekey every direct `requestLayout` caller (`ER-B`). The mutation that deletes `noteNamed` (M2, record 201) reddens the swap-back, focus, lifecycle and graft pins: the keyed level without the note is the M15 shape and is not enough.
4. **Why not a per-position type table with an `ID-C` reset** (the earlier judgement, `FV-C` item 3, and `Tasks.md`'s wording): a sweep-time reset runs after B has already bound, so B would read A's value for the swap frame and the sweep would then delete B's seed; and a single shared id leaves every other id-keyed store shared across the swap (`LifecycleStore` sees a continuing key and fires nothing,
   `AnimationStore` carries the `$anim` baseline, `ContentMemoStore` shares an entry). A distinct id corrects all of them at once and needs no new channel.
5. **Paths move.** Everything an erased element registers sits one level deeper (`hitboxes`, accessibility records, `$state`, `$focus`, `$ax`, the layout nodes), and only the position's own element bounds stay at `P`. "Boxing every child moves no path" (`ElementBuilder.swift`, the `AnyElement.swift` header, `IdentityTests`) was refuted and is corrected there. Test updates for the extra level:
   `twoErasedSiblingsDoNotShareOneStateEntry`, `anOnOpenURLOnAnErasedElementIsOwnedByTheScopesOwnId` (the owner is the level, `owner.parent?.component == .named("r")`), `aHiddenElementInsideAnyElementIsHiddenUnderTheProposalAuthority`, `aDeclaredSizeBelowThePaddingKeepsItsFixedFrame`, `reversingKeepsIdentityPaintOrderHitOrderAndAccessibilityOrder`, `aStretchedChildFillsTheLineOnItsCrossAxis`,
   `aGrowingChildTakesTheRemainingMainSpace` (hand-built paths and `AnyElement.contentID(under:)`). **Seven tests, not the three the plan predicted**: the four lowering tests build their own `AnyElement` containers; a path read, not a behaviour. The instruments of the new tests declare their stored properties in one order, because a `@State` slot is named by the property's position (`$state<k>`): two types with the state at different positions
   never shared a slot (the first run of the new file read `[20]` with the old code).

## ER-B: a direct caller owns its identity; the carried sites

1. `AnyElement.requestLayout(_:pass:)` (and `prepaint`, `paint`) keep the id the caller passes: the custom `Button`/`Toggle` bodies, `StyleLabel`, the three strips and the presentation background use them, and a style body's `@State` must stay at the control's id. Pinned by `aDirectRequestLayoutMintsNoLevel` (a custom-style `Button`'s hitboxes carry no `$erased` level; the control, a group-entered `AnyElement`, carries one).
2. **Carried, not fixed and not probed:** `PanelBackgroundContent` (`AnchoredPresentation.swift`) can swap at one `backgroundID`; a style body under an opened existential could swap at one `Button` id (an inference, not compiled). Neither is reached by the in-tree callers; a caller that swaps types at a direct site shares its slot as before.
3. **Inherited from `.id`:** a position not evaluated on the frame before the swap (a `List` row out of its window) departs nothing, so the old level stays a bounded tombstone (`TB-AH`); the `$ax` slot is exempt from the reset.

## ER-C: the residues (211, 212) and what is unmeasured

1. **211.** SwiftUI makes a modifier part of the erased type: `AnyView(X)` to `AnyView(X.background(.red))` and `.padding` to `.opacity` reset (`AV3d`, `AV3e`). A legacy decoration on a `StyledElement` returns `Self` (`Box.background`, `Stack.background`) and writes the element's `Style`, so the key is unchanged and the state is kept; a different `ModifiedContent` layer is a different type and resets, as SwiftUI's.
   Pinned wrong on purpose by `aLegacyDecorationIsNotATypeChangeUnderAnAnyElement` (arm `background`; arm `paddingToOpacity` is the control that the key sees a layer change). A fix would key the level by the decoration too.
2. **212.** A swap runs `disappear A` before `appear B` in SwiftUI (`AV5a`), where `if`/`else` and `.id` appear first (`A4`, `E2`). A swap is one build here, so `LC-F`'s order applies: `appear B`, `disappear A`. Recorded, not special-cased; pinned by `aSwapRunsDisappearAndAppearOnce`.
3. **Unmeasured.** `AV6a`/`AV6b`: the old content's `disappear` fires in the swap's own step under `withAnimation(0.6)`, with or without `.transition(.opacity)` inside (control `T1` delays it past the animation), so there is no removal ghost, as MetalUI draws none; whether SwiftUI cross-fades the swap on screen was not read (no pixels; the
   session was locked and `preflightScreenCaptureAccess` was false). Row 98 (the default cross-fade, R4-3) is not amended. `AV6c`: B appears at its settled value and A returns settled, but the per-line logging slows the animation clock so "mid-flight on return" is not separated; `aSwapUnderAnAnimationIsInstant` pins MetalUI's side (no ghost, no baseline carried).
