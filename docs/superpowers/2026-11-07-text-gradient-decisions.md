# A gradient `foregroundStyle` on text - decisions (prefix `TG-`)

Rulings for R4-5 PR D: a gradient used as a text's `foregroundStyle` paints across the glyphs' ink instead of lowering to its first stop (**divergence 975 narrowed, not retired**; live 209, next label 226, unchanged). Branch `feat/text-gradient` (master `d0cceec6`). Record 221. Evidence: the probe `docs/probes/swiftui-text-gradient.swift` (arms `TG0`..`TG14`; compiled, six byte-identical runs, 2026-11-07; `TG12` and `TG13` not measurable). Next unused id: `TG-H`. Carried: see `TG-G`.

## TG-A: one storage, end to end

`EnvironmentValues` stores `foregroundStorage: ShapeStyleStorage?`; `foregroundStyle: Color?` is computed over it (the getter is `representativeColor`, the setter writes `.color`), so every existing reader and writer (`Button`, `Toggle`, the measurer, the hierarchical code, `Color.swift`) is untouched and **a colour written below a gradient clears it by construction**. The fingerprint keeps one field of that name `foregroundStorage` (the count stays 27; `differences(from:)` names it `foregroundStorage`). `Text.foregroundColor` (public) and `ProposalText.foregroundColor` are computed over an internal `foregroundStorage`, source-compatible (`docs/migration.md`; guard `textForegroundColorStaysPubliclyReadableAndWritable` pins that it stays publicly settable). `TextRunRequest.foreground` and `TextStyleRequest.foreground` are `ShapeStyleStorage?`; `ResolvedTextStyle` and `TextRunPaint` keep `foreground: Color` (the representative, read by selection, links and decorations) and gain `gradient: GradientFill?`. `ShapeStyleStorage.gradient` is `indirect` (`GradientFill` is 41 bytes); `MemoryLayout<Text>.size` is unchanged. **A stored field of a public type changed: `swift package clean`.** **A setter that runs while a tree is built must not use a `Color?` map closure** (it carries a main-actor check and traps on a secondary thread, `everyProductionTreeBuildsOnAOneMegabyteThread`): explicit `if let`.

## TG-B: the writers

`ElementGroup.foregroundStyle<S>` stores `shapeStyleStorage(style, in:)`; `Text.foregroundStyle<S>` and `ProposalText.foregroundStyle<S>` store `builderStorage()` (divergence 976 unchanged: a custom composition resolves in a bare environment). `HierarchicalShapeStyle.resolve` over a gradient parent returns the gradient with every stop's opacity times the level's factor (probe `TG9`, `P14`); over a material parent it keeps the representative colour. A bare shape's default fill (`paintShapeFill`, `declared == nil`) takes a gradient `foregroundStorage` through the same dispatch `paintStyleFill` uses (probe `TG14`). A colour sink (`border`, `tint`) is `SS-C` item 3, unchanged.

## TG-C: painting - the glyph run is the mask, the gradient raster is the content

A gradient text is **one masked offscreen group per equal gradient** (`GroupMark(…, inkMask: true)`): the content is one `.gradient` primitive over the ink's box and the mask is the ink, the glyph records (`Frame.inkGlyph`) and decoration rects (`Frame.inkRect`) at the representative RGB at **alpha 1 and no `activeOpacity`** (the content carries the fade, so an opacity fades once, `TG7`). `CM-A`'s destination-in pass multiplies the group by the glyph coverage, so the alpha equals the solid text's (`aGradientTextsCoverageIsTheSolidTexts`). **The span is the ink**, `Frame.inkBounds`, the union of the device bounds of the glyph quads and decoration rects of one gradient's ink mapped back to points (probes `TG3`, `TG2d`, `TG8`: not the layout box, a frame or padding); a wrapped text is one span (`TG1`, `TG2`); runs carrying an equal gradient share one span across the runs between them (`TG5`; `drawStyledText.inkGroups` groups by gradient equality); an underline or strikethrough with no colour of its own follows the run's gradient and **extends the span** (`TG10`, `TG10v`; `TextRunPaint.underlineFollowsInk`, `strikethroughFollowsInk`); an own colour stays. A shadow sees one leaf (`GX-J`) and casts the shadow colour (`TG6`: the group's silhouette is gradient alpha times coverage and `needsGPU` routes a marked leaf to the filtered group). The group travels the paint scopes as one primitive with one mark and **no `PaintScope` is pushed**. The plain path (`Text.paintGlyphs`, `ProposalText`) calls `drawGlyphs` when there is no gradient (byte-identical to before) and `drawGradientGlyphs` otherwise. Pin: `TextGradientTests` 1-20.

## TG-D: a mark's mask is N primitives

`GroupMark.mask` was an array read as one element at seven sites; each is a loop now: `flagMarkMasks`, `insertMaskedGroup(_:mask:inkMask:)` (the ellipse bake only for a one-element mask), `cutToEntryClip` (green by construction: an ink element's content mask is unbounded), `RenderEffect.apply` (any unmappable element drops the content), `CapturedPrimitive.replayed` (a drag preview), the `Scene.capturedGroup` ghost read-back (`DefaultTransition`: every primitive of the mask scene) and `RetainedTranslation.movedLeaf` (unreachable, `TG-G`). **A mask scene holds rects, glyphs and images** (the `Scene.insert` precondition message, `Scene.groupMasks`, the `GroupMark.mask` doc, the SDL and fixture comments and `drawing.md` say so; this amends `CM-A`'s "rects and images only" and nothing else). The mapping audit found no site the plan did not list.

## TG-E: limits

A gradient text over 8192 device pixels on a side (`insertMaskedGroup`'s oversize branch with `inkMask`) draws **its ink** at the first stop's alpha times the content's opacity, cut by the content's clip (today's first-stop drawing; `masksFlattenedOversize`), not the content's gradient box. A renderer that cannot make the mask scratch (Metal `lastMaskAllocationFailures`, SDL `mask_failures`) draws the group **unmasked** as `CM-A` does, which for a gradient text is the gradient over its ink box: a resource-exhaustion degrade, named and counted (the alternative, a per-group "ink" flag that draws nothing on failure, would cost fixture v10). **What divergence 975 keeps:** a material as a text's `foregroundStyle`, `border` and `tint` with a gradient or material, a material stroke, the text of `TextField`/`TextEditor`/`drawText`, and these two limits.

## TG-F: SDL, D3D12 and the fixture

**No renderer, bridge, HLSL, blob or fixture-format change**: the mask pass runs `draw_run` for every run kind, `SDLGroupSet.Builder.append` and `FlatFrame` already shift mask glyph transform indices, and a v9 mask body already stores `mask.glyphs` (the reader and `validate` accept glyph runs: stop condition F did not fire; `aGlyphMaskBodyRoundTripsInVersionNine`). Parity frame 19 (`gradientTextFrame`, `--expect 20`): a linear label, a wrapped two-line text, a rich text with a gradient run and an underline, a shadow, a rotation, `compositingGroup().opacity(0.5)`, a radial label, a `Rectangle().foregroundStyle(g)`. SDL-over-MSL frames 0-19 read 0/0; llvmpipe Vulkan frame 19 reads outside 0 px, inside 16901 px max D3 (<=8). **The parity tolerance regions need no change**: a mask body's glyph quads lie inside the group's own quad, which is an image of the root scene and so in `spriteMask()`. A mask glyph quad is glyph-sized, hence finite (`CM-I`); never `unboundedMask` as a glyph's bounds.

## TG-G: carried

A moved `.equatable()` occurrence holding a gradient text is **refused by name** `unlistedKind:gradient` (`FS-E`'s allow-list is rect, glyph, image, and a gradient fill was always refused), not by `innerScope`; it repaints and equals a retention-off frame (`aMovedOccurrenceHoldingGradientTextIsRefusedByNameAndEqualsAFreshFrame`). Nothing differs on screen, so this is no divergence. Listing `.gradient` in the gate (moving the content's `local` and the ink by the translation) would make it a hit; until then `RetainedTranslation.movedLeaf`'s N-element mask loop is unreachable (as `CM` M27) and no test can redden it. `cutToEntryClip`'s loop is green under mutation for its reason in `TG-D`. A counter whose digits change width can re-raster the gradient strip (the key holds the ink rect); a counter of fixed-width digits does not.
